# 第二章原生客户端迁移

第一章原生补丁的 40 处固定指令签名在已验收的第二章重建镜像中逐项核对，同地址匹配数为 0。第一章独立补丁和 JPEG 代理也有各自的启动识别条件。保留第二章原有 JPEG 模块及原生宿主作为默认路径。

| 迁移顺序 | 当前覆盖 |
| --- | --- |
| 启动与双开 | 第二章宿主已有双开、方向键和城镇外观保护。第一章界面及账号流程可从托管启动器复用 |
| 锐利缩放与坐标 | 可选适配器复用第一章 D3D8 COM 缩放和坐标转换。只修改匹配签名的外部窗口尺寸和对应输入入口，保留内部 640×480 |
| 后台节流 | 已定位第二章的非激活等待和窗口激活处理分支，待隔离双开实测 |
| 浏览器、滚轮、性能与日志 | 充值页保留游戏原有浏览器，并接入本机测试页面。鼠标滚轮、帧率绘制、原生文本日志和声音分别核对客户端入口 |
| 游戏行为与调试 | 背包页、物品和商城、组队战斗、翻牌、死亡、召唤、换频道、自动输入和移动诊断需要分别核对第二章结构和行为 |

适配宿主默认沿用原始显示。实验启动可设置 `DFL_S1C2_PRESENTATION_FILTER` 为 `sharp`、`point` 或 `linear`，并通过 `DFL_S1C2_WINDOW_WIDTH` 和 `DFL_S1C2_WINDOW_HEIGHT` 指定第一章已有的六个 4:3 预设之一。选项或签名校验失败时保留原始显示。

`Build-PresentationHost.ps1` 从独立目录中的验收宿主源码构建可选宿主，校验源码和重建镜像摘要，随后执行映像适配与呈现策略测试。映像测试验证禁用及签名不匹配时零写入、外部窗口尺寸、内部尺寸和三个重定向入口。显示画质、鼠标点选和窗口设备恢复仍需用真实客户端确认后才能默认启用。

第二章商城充值和黑钻使用游戏原有的 460×316 内嵌浏览器。兼容宿主校验原游戏的导航调用后，将两条支付地址转到启动器提供的本机页面。页面资源、表单和内嵌结果沿用第一章实现。管理器默认关闭测试充值，启用并重启服务后可使用。

`ChapterTwoPaymentProtocol` 使用当前进程的 URLMon 注册处理本次启动的充值路径，复用隔离进程外的本机页面服务。能力为空的 AppContainer 中已用真实 x86 内嵌浏览器验证页面和脚本加载、表单提交和内嵌结果显示。商城按钮、充值弹窗尺寸和关闭后键鼠操作仍需整包真机复核。

2026 年 11 月 9 日合并主分支后，`ChapterTwoInventoryTab` 已接入宿主。拾取新增物品或数量增加时保留玩家选择的背包页，原生手动切页继续生效。构建流程执行真实第二章映像的插入、数量修改、手动按钮及失败恢复检查。此项仍待游戏窗口实测。

同轮更新了共用路线读取，支持目录末尾的八字节对齐。新版第二章 PVF 已执行跨区路线夹具。第一章新增的“牛来”地面物品归拢仍待第二章结构验证，第二章会话保留普通聊天处理。迁移范围与验证结果见 `knowledge/decisions/2026-11-09-chapter-two-main-sync.md`。
