# 第二章本地真机测试流程

适用于 Windows 上用隔离测试服和真实第二章客户端验收登录、城镇通行、装扮栏销毁与限时称号等功能。首次准备角色时先跑通地图，再保存一份可重复使用的基线。2026-11-22 的环境和用户结果见[本地测试交接](../decisions/2026-11-22-local-test-handoff.md)。

## 1. 准备环境

1. 记录服务端提交、客户端包版本、宿主版本或哈希、配对的客户端与服务端资源，以及待测功能。确认服务端构建确实包含本次修复。服务端使用该章配对的 `Script.pvf`，客户端使用客户端格式的资源。
2. 使用专用 QA 账号、客户端目录、配置和存档。服务端停机后从干净基线复制出本轮可写存档，令 `server.json` 的 `DFLegacy.DataPath` 指向该副本。基线和生产存档留作只读来源。同网段或同机已有实例时核对端口归属，避免连错服务。
3. 优先复用游戏仓库 `AGENTS.md` 指定的普通完整性测试安装。开测前核对安装身份和权限。确需新副本时，先按该文件的空间与目录规则取得用户同意，再解压或使用 `robocopy /COPY:DAT` 复制到约定目录。保留完整包的入口、App、Updater 和包内 V4 已安装回执，运行时日志和解包缓存可重新生成。不要从无关安装拼接回执或替换受清单管理的固定入口。用 `icacls` 检查测试目录及启动 EXE 是否带有 `Low Mandatory Level`，从普通交互桌面启动。工作区或 `.tmp` 中的副本有可能继承低完整性标签。
4. 本地 LAN 直连按下表配置。换网线、Wi-Fi 或重启后，重新用 `Get-NetIPAddress -AddressFamily IPv4` 核对实际网卡地址。若启用域名中继，按其独立配置契约准备服务端通告地址，勿混用两套配置。

| 配置位置 | LAN 直连设置 |
| --- | --- |
| 客户端 `launcher.chapter2.json` | `ChapterTwoServerIpv4` 填本机当前的 LAN IPv4，移除 `ChapterTwoServerHost`。使用 QA 配置并设置 `StartServer=false`。验收指定构建时可关闭自动更新，单独安排安装和修复验收。 |
| 服务端 `server.json` 的 `DFLegacy` | `ChapterTwoRemote=true`。监听地址和玩家拨号地址分别配置，`GameplayDatagram.AdvertisedHost` 及启用时的 `FallbackRelay.AdvertisedHost` 使用客户端可达的同一个 LAN IPv4。 |
| 端口 | 核对实际配置与监听。本轮使用 TCP 入口 `42312`、频道 `47001` 及地区频道 `7100–7105`、账号服务 `48091`，另有角色和玩法 UDP。同一个端口号的 TCP 与 UDP 分别检查。 |

分体整包的托管登录器和更新器可能分别从包根与 `client` 下读取配置。副本已有两份 `launcher.chapter2.json` 时核对它们的服务器地址和更新开关一致，并以启动日志确认实际生效值。维护入口、发行号和安装回执的规则见[构建测试发布](build-test-release.md)与[桌面应用](desktop-apps.md)。

## 2. 准备角色与地图

**满级角色也可能无法进入赫顿玛尔或阿伐利亚营地。** 区域用例需要对应地图的取得或解锁状态，等级、频道列表或 GM 传送都不能代替正常通行。用准备好的专用 QA 角色做区域功能验收，另留新角色用于验证创建角色、初始流程或地图解锁本身。

| 需准备的数据 | 开测前的验收动作 |
| --- | --- |
| 赫顿玛尔地图 | 确认角色已按当前第二章资源对应的流程取得地图并完成所需使用或解锁。从正常城镇入口走到用例指定区域，核对地图名和实际到达点。 |
| 阿伐利亚营地地图 | 单独确认该地图的取得或解锁状态，从正常入口实际进入阿伐利亚营地。如用例需要特定 NPC、仓库入口或副本门，继续走到该位置再确认。 |
| 任务和道具进度 | 保留两张地图涉及的前置任务、完成记录及道具或解锁状态。优先复制已正常走通的 QA 角色所在隔离存档。新角色缺地图时按当前资源的任务流程补齐，记录实际任务和道具 ID，避免套用其他章别或版本的 ID。 |
| 角色基线 | 记录 QA 账号名、角色及职业等级、频道、出生点、两张地图的状态和已走通的入口。双人及组队用例逐个角色检查。退回角色选择或重登一次，确认通行状态可重现，再停服备份基线。 |

如果地图上没有目的地、正常入口进不去，或只有 GM 传送能到，先将该区域用例标为「前置未满足」。需要观察不同区域的行为时，优先用已准备好的角色跑通路线后再装载有时限的道具夹具，避免找路时称号已到期。

## 3. 运行用例

先停服准备当轮数据，再启动隔离服务。确认日志已加载正确资源、入口和目标频道开始监听，且日志中通告的地址与客户端配置一致。整包从自己的正常入口启动，v1.0.18 测试副本使用根目录 `DFOLauncher.exe`。先走完登录器、频道选择、角色选择、进游戏和实际键鼠操作，然后执行目标用例。

| 用例 | 数据和步骤 | 预期及证据 |
| --- | --- | --- |
| 新版客户端启动与进游戏 | 记录实际启动路径、版本和频道。进入角色，再操作键盘和鼠标。 | 到达可操作的城镇。留登录器日志、服务端日志和对应时间。显示频道列表只代表已到频道选择。 |
| 区域通行 | 使用已取得或解锁两张地图的角色，分别从正常入口进入赫顿玛尔和阿伐利亚营地。 | 可到达各自目标区域。记录起点、入口、终点和重登结果。游戏功能需要在指定区域测时，记录实际地点。 |
| 城镇装扮栏销毁 | 在可进入目标城镇的 QA 角色装扮栏准备可丢弃样本，另留一个对照装扮。用游戏界面确认销毁样本后重开装扮栏并重登。 | 目标样本消失且重登后不回来。对照装扮、背包和金币不受影响。需要定位时核对服务端 CMD18 的 `listType=1`。 |
| 单件右键入库 | 在同一 QA 角色的背包准备一件未穿戴装备、一个数量为 1 的可堆叠物品和一摞多件物品。打开角色仓库并逐个右键，最后重开仓库和重登。 | 前两件直接入库，多件堆叠进入数量选择。另查可合并堆叠和满仓拒绝，记录两边最终数量及宿主哈希。 |
| 限时称号在线到期 | 按下表种入六个有期限的新实例及一个永久对照。实际进入角色，先确认都在，再保持在线按顺序观察。仓库用例在目标城镇打开仓库确认。 | 到期前存在，到期后从对应位置消失。装备槽刷新、背包刷新、仓库重新打开后的状态分别记录。永久对照仍在。 |
| 到期持久化 | 在线到期后退出并重登。需要验证离线回收时用另一轮夹具，在到期前退出，到期后再登录。 | 已回收称号不再出现。需要验证邮件时另建一封带限时附件的 QA 邮件，单独检查附件消失与邮件正文保留。 |

### 限时称号夹具

示例沿用 2026-11-22 的角色与物品组合。时间偏移从本轮写入绝对到期时间时开始。先完成地图和登录预检，再停服备份、检查目标槽位为空或已有约定样本，按服务器当前时间重新设置到期并立即启动。首个到期点应留足启动、选角和到达仓库所需时间，以下只是一种排期。

| 位置 | 物品 ID | 称号 | 相对写入时间 |
| --- | --- | --- | --- |
| 装备槽 10 | 26040 | 斗士 | +10 分钟 |
| 背包槽 10 | 26015 | 幸福恋人 | +11 分钟 |
| 背包槽 11 | 26029 | 彩虹色希望 | +12 分钟 |
| 背包槽 12 | 26034 | 玛尔战争英雄 | +13 分钟 |
| 仓库槽 0 | 26038 | 瞬发者 | +14 分钟 |
| 仓库槽 1 | 26039 | 测验达人 | +15 分钟 |
| 背包槽 13 | 26001 | 卡妮娜的希望☆ | 永久对照 |

- 修改 `AvatarExpiresAtUnixSeconds` 前确认服务已停止，备份后仅编辑隔离快照。已被清理的实例需要从测试基线重新准备，或在隔离快照中为规定槽位加入新的测试实例 ID。保留已有到期墓碑，避免复用已回收的实例 ID。写入后复读装备、背包和仓库各槽及永久对照，记下本地绝对时间。
- 服务启动或登录可能先结算已经过期的样本。若还没看到到期前状态，就把这一轮标记为夹具过期，停服恢复或重种后再观察。手工时间戳覆盖回收和刷新，模板 `[usable period]` 的首次计时需单独用正常获取流程或定向 smoke test 验证。
- 这组验证关注到期后移除。旧客户端未提供称号倒计时显示，测试人员按服务端绝对到期时间记录。

## 4. 快速排查与收尾

| 症状 | 检查顺序 |
| --- | --- |
| 登录器提示入口不可达 | 查测试服进程、`42312` 监听及当前 LAN IPv4。对照账号服务与客户端地址，确认未误连其他实例。 |
| 已有频道列表，选频道卡住 | 查看目标频道端口是否收到连接。未收到时核对通告 IP、直连与中继模式。收到连接却记录 `Could not recover the channel payload seed` 时，核对 LAN 模式的 `ChapterTwoRemote` 并重启测试服。仅设置试验密钥环境变量的分支要求连接两端均为回环地址。 |
| DirectInput 初始化失败 | 检查运行路径和进程完整性。历史探针中 `0x1000` 为低完整性，同时出现注册表创建被拒及 `0x80004005`。先换到正常继承权限的独立测试目录，再测试游戏。保留系统安全设置和 DirectInput 注册表。 |
| 更新器退出 1，登录窗口未出现 | 保留 `.dflegacy/bootstrap/bootstrap.log`、登录器事件和安装回执。核对固定入口、Updater、App 与同包清单及 Windows 文件属性。可用同版本干净整包另建副本复查。 |
| 能进游戏，无法进入区域 | 对照角色基线，检查对应地图、任务及通行状态，再走正常入口确认。若仅这个角色缺前置，补齐数据后重测。 |

保留 `launcher.log`、`chapter-two-client-*.log`、`chapter-two-events-*.log`、服务端同一时间段日志，以及状态截图。反馈时附版本、测试角色、所在区域、测试时间及通过、失败或未执行的用例，分享前检查日志中的账号敏感信息。测试结束后按本轮约定关闭隔离进程并归档本轮存档。下次从已验证通行的基线复制，重新计算当轮截止时间。自动化和真机结果分开记录，参见[测试与证据](build-test-release.md#验收记录)。
