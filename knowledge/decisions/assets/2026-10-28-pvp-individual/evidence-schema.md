# Evidence schema and reproducibility

`native-packets.json` is `act1-pvp-native-capture/v1`, re-decoded from closed private copies of both native netdumps. All gameplay TX frames consume the rolling cipher and have an independent plaintext CRC32 equality check. Only CMD1/3/4/53–62/120 and NOTI41–49 fields are exported. Entrance/authentication packets are not exported. Login account UID, credentials, room/password strings, raw hex, IP addresses and full character/account state are omitted. Runtime seat UIDs are protocol correlation values, not account identifiers. Socket addresses are report-local aliases; remote port is retained. Capture hashes identify full input bytes; line numbers and timestamps identify selected frames.

The original private report remains unchanged. `binding.original_report_sha256` links it to the closed-copy derivative. Its event arrays, TCP counters and UDP summaries were re-derived from frozen raw bytes and compared exactly. `binding.raw_sources` exposes names/hashes/lengths only; all raw logs and complete pre/post state remain private. `deployment_sha256` is the original capture's deployment hash; `binding.deployment_sha256` identifies the stopped deployment frozen with the raw copies. The two legitimately differ after stopping the process.

TCP interpretation follows the actual production builders/readers in `GameProtocolEngine.Pvp.cs` and `GameProtocolEngine.cs`. Results are mode0 individual; NOTI48 precedes NOTI47 in the observed coalesced reply. Sequence numbers, recipient VP, signed PvP EXP delta, submitted rank scores and record counters are preserved. Stats retain their wire indices, without invented names. A report status of `observed` is parser status, while `native_acceptance: NOT_ASSESSED` deliberately remains the capture tool's own verdict. Native acceptance requires the separately reviewed UI, input and canonical-state evidence.

UDP interpretation has an explicit limit: the generic `GameDatagramProtocol` seven-byte encrypted application decoder does not cover all native opaque MT application/fragment forms in these captures. Its `application_crc_invalid` and `unparsed_datagrams` counters are preserved as decoder diagnostics, not evidence of network corruption. No complete native UDP application-CRC claim is made. The independent checker compares reliable/unreliable/ACK-shaped block counts across A-TX/B-RX and B-TX/A-RX. Native movement, HP changes, actual death and result UI provide gameplay evidence beyond those traffic counts. NAT/ACK shapes alone do not prove readiness. The server's opaque relay does not require every native application to match the managed server-generated application format.

`native-state-delta.json` contains only changed PvP counters and equality results from the private canonical snapshots. Before/after full state hashes bind that audit. Accounts, character identities, all non-PvP character fields, other characters and non-PvP ledgers were compared; only two characters' expected PvP counters and three unique dual-award receipts changed. Receipt GUIDs/fingerprints stay private; public receipts retain ordinal and A/B awards. Snapshot equality is a statement about this run, not a general proof of concurrency safety.

`native-combat.json` retains only HP/state samples from the read-only native observer. `native-responsiveness.json` retains 22 observations per role. Both include hashes of private sources. They contain no memory addresses, process paths, account IDs or arbitrary dumps. The operator used native built-in UI/key input and VM_READ observation; no packet/state injection was used.

`verify-native-evidence.py` independently checks asset hashes, three ordered lifecycles on both clients, submitted rank/result agreement, recipient counters against both canonical awards, the real death path, four login modes in the same PID, peer traffic symmetry, native HP progression and responsiveness. Run `python -B verify-native-evidence.py` from any directory. It reads only this asset directory and writes nothing. `native-check.json` is its captured output. The hash manifest excludes itself and that derived output to avoid a cycle; all input assets and the executable checker are included. It does not claim to reproduce raw decryption without the private logs or independently inspect UI images.

The 18 JPEGs are byte-identical original native captures. Character display names visible within game UI are retained as test-fixture visuals; authentication/account records are not included. Test/build logs are existing historical outputs copied byte-for-byte. No build or game run was performed during evidence packaging. The native runtime identity is historical managed `cacab2e` plus native `3a35188`, with final Gold build/deployment/integration binding still pending.
