## Exact read-only calculation

Use native uint32 arithmetic, converting the final bit pattern to signed int32 by memcpy/bit_cast, never C++ signed overflowing subtraction.

```text
Clock(T):
    if Secure(T+0x10) == 0: return 0
    if Secure(T+0x18) == 0: return 0
    if Secure(T+0x20) != 0: return Secure(T+0x30)
    i = Secure(T+0x08)
    require 0 <= i < 16
    slot = 0xCFD278 + i*4
    if ReadByte(0xCFD44C) != 0:
        base = Secure(ReadU32(slot))
    else:
        base = ReadU32(slot)
    return uint32(base + Secure(T+0x28))

duration = SecureSigned(Skill+0x34C)
if duration == -1:
    nativeRemaining = -1
    cooldownBlocked = true
else:
    deadline = SecureU32(Skill+0x354)
    nativeRemaining = int32_bits(uint32(deadline - Clock(0xB75978)))
    cooldownBlocked = nativeRemaining > 0
```

For a public nonnegative remaining field, `max(nativeRemaining, 0)` is appropriate only for finite duration. Preserve the -1 case explicitly (raw -1, null remaining plus `pending`/`indefinite`, or another unambiguous existing contract). Mapping sentinel -1 to known zero is incorrect because the dispatch predicate blocks. Expired finite cooldown returns negative in the native getter; that is normal and should not turn the whole snapshot invalid. An idle skill initialized with duration/deadline zero can likewise return a negative native remainder. Native code has no clamping, rounding, seconds conversion, or wall-clock lookup in this getter.

The predicate reads duration twice and has a transient-state branch if the second read changes to -1; do not recreate this race intentionally. Require a coherent/stable observation. Negative duration values other than -1 have no named native meaning proven here; observation can report raw data while a higher-level validated finite-duration contract should fail closed rather than inventing a state.

## Timebase, pause, and wrap

The 16 indexed base clocks are accumulated by 0x8FD8A0. Its source IAT slot 0x9984F8 is **winmm.dll timeGetTime** (verified PE import). It computes 32-bit source delta, converts that delta via signed x87 `fild`, applies per-index speed percentage from 0xCFD2B8 + index*4 and float 0.01 at 0x99A770, maintains fractional carry at 0xCFD238 + index*4, and adds the integral increment to the indexed accumulated clock. These arrays also use plain values or secure pointers according to 0xCFD44C. Read the resulting accumulated clock; do not reproduce floating-point accumulation from host wall time. A normal timeGetTime wrap with short frame delta is handled by modulo subtraction. A source gap >=2^31 ms is outside ordinary signed-delta behavior.

Skill initialization 0x4F3578–0x4F358F calls 0x8F4060(T, 1), then 0x8F3E80(T, 0, 0) to start/reset the skill timer. Selector changes preserve the current time by adjusting the offset. The observer can implement all 16 selectors or require the proven current selector 1 and mark any other selector unsupported. Do not silently assume index1 without reading/validating the selector.

Timer 0x8F3F60 returns zero if enabled/started is zero; returns +0x30 if paused; otherwise returns indexed base plus offset. Getter does not extrapolate between base-clock updates. Function 0x4C5C20(bool) pauses/resumes both 0xB5ECC8 and 0xB75978: nonzero invokes 0x8F3FC0, zero invokes 0x8F3F00. Thus application pause can freeze cooldown while timeGetTime keeps advancing. The exact user-visible screen/event triggering this manager is not named by this limited analysis; do not claim every menu pauses.

Deadline creation, offset additions, and deadline-minus-current all wrap modulo 2^32. The predicate's signed-positive test handles usual wrap-crossing finite cooldowns shorter than 2^31 ms. A difference with sign bit set is native non-blocking, not an enormous unsigned remainder. Test modulo cases and preserve native behavior. The special duration -1 branch has priority over deadline/time and cannot be interpreted through subtraction.

## Independent native consumers and lifecycle

1. Display path: Skill draw routine 0x4F2990 reaches 0x4F2CAC when its `[ebp+0x20]` display-cooldown argument is nonzero. It obtains native remaining from 0x4F28E0 and secure duration from +0x34C, then passes both to overlay routine **0x45C240**. That independent consumer skips duration zero, uses signed positive remaining for the active overlay, handles duration -1 as active/pending, and has a post-expiration visual effect until remainder <= -450 ms. A finite negative remainder is therefore explicitly consumed normally. Draw callers include 0x7BA3D7, 0x7BBA88, 0x7FE09D, 0x83EA63; the 0x7BBA88 call sets the cooldown-display argument true.
2. Dispatch path: actor routine 0x49C600 calls **0x4F2DF0** at 0x49C702; separate caller 0x4DFB2F also invokes it. The usability agent is tracing surrounding gates. Neither should be called merely for observation, particularly 0x49C600 which can consume resources.
3. Pending/indefinite lifecycle: **0x4F3940** calls the setter with -1 for the target skill and related skill IDs in secure-int vector +0x1F4..+0x1F8. Actor wrapper 0x4938D0 calls it. This proves -1 is actively written, not just a corrupt/uninitialized value.
4. Finite lifecycle: **0x4F4C30** calculates duration via 0x4F4B50, multiplies by its supplied float factor, converts to int, then calls the setter; it applies the same duration to related skills in +0x1F4..+0x1F8. Caller 0x4938B9 supplies multiplier1.0; caller0x495396 has another factor. Last runtime duration +0x34C is authoritative for the active overlay; it can differ from nominal definition data and can be shared across skills.
5. Lazy allocation: actor virtual +0x51C = **0x4A3510** allocates a 0x36C Skill and loads definition data when the actor's slot is null. Even actor level virtual +0x508 = **0x493DC0** forwards through +0x51C after its initial non-null test. Observe existing pointer slots and secure fields directly.

Nominal-duration calculation is separate from current remaining and unnecessary for U05's remaining-ms observation. For reference, 0x4F4B50 selects a secure int from the level table +0x1E4..+0x1E8, then applies actor factors based on secure skill+0x208; this research does not label those actor factor categories.

## Meaningful validation recommendations

* Reader fixture containing actor slot, correct Skill type/owner, secure duration/deadline, Timer fields, and plain base clock. Use duration3000/deadline8000/current5000 => remaining3000/blocked; advance base to7999/8000/8451 => 1/0/0 public remaining and true/false/false blocked. Retain raw -451 for native-comparison diagnostic if exposed.
* Repeat the same contract with 0xCFD44C nonzero and the slot pointing to a secure int. This catches the easy-to-miss pointer-vs-value error.
* Pause fixture: timer paused with frozen5000 and base advancing 5000→9000 gives unchanged remaining. Resume offset chosen to preserve5000 then base advance yields normal countdown. This catches using tickMs/timeGetTime directly.
* Nonzero running offset and selector1: choose different clock0/clock1 values; ensure selector determines countdown. Cover disabled and not-started (native clock0), and invalid selector (unknown, no out-of-bounds reads).
* Duration -1 with past/future/zero deadline: raw -1 and blockedtrue in every case. No need to read deadline or clock on this branch, though stable duration/identity validation still matters.
* Wrap vectors: current0xFFFFFFF0/deadline0x20 =>48; current0x20/deadline0xFFFFFFF0 =>raw-48/public0; exact difference0x80000000 => native signed negative/non-blocking. Avoid UB in C++.
* Secure-header corruption, mirror mismatch, invalid secure-pointer slot, unreadable Timer, wrong Skill vtable/owner, or field/identity changing during capture => unknown plus specific error rather than known0/ready. A failure in one instantiated learned skill should not silently remove it from the level inventory.
* Coherence: recheck Skill pointer/owner/level and duration/deadline around clock capture; validate timer control fields, mode, selected slot pointer, global manager/key identity. Mode/selector/pause changes require discard or bounded retry. Normal monotone clock progression can be bracketed instead of insisting that the clock never advances during the whole capture.
* Data-driven live acceptance: choose an actual learned instantiated skill with positive nominal cooldown from runtime data; record idle -> native cast -> active countdown -> ready, with actual observed duration as the expected upper bound. Validate same skill identity/level, bounded decreasing finite remaining, positive active sample, expiry0, and resource/usability separately. Include a real pause/resume if an authorized native action exists; absence of a pause trigger is a fixture case, not a reason to alter memory. No native getter is required for acceptance: the UI overlay and native dispatch predicate independently corroborate the proven fields. Do not hard-code a skill ID or a guessed cooldown length. Related skills may enter shared cooldown together.

Remaining uncertainties are semantic naming of the -1 lifecycle (pending/indefinite rather than an asserted exact casting phase), user-visible pause trigger names, and actor-factor categories in nominal duration. The remaining-ms calculation and native blocked predicate are fully derived from the executable.
