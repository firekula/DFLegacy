# v1.0.17 整合包首次启动失败与 r2 修复

- 日期：2026-11-20（Asia/Shanghai）
- 结论：v1.0.17 旧 7z 整合包缺少 V4 安装记录，首次启动被判为未受管目录；已重制并双站发布 `v1.0.17-r2`。客户端程序、更新清单、服务端镜像均未改。

## 症状

在干净目录解压旧 `DFLegacy-Chapter2-Full-v1.0.17.7z`，运行 `client\DFLegacy.Launcher.exe` 弹「更新或自动修复未完成。请查看更新程序提示后重试；本地恢复副本已保留。」

## 复现与根因

- 复现目录 `G:\tmp\pkg-1017-repro`；`client\.dflegacy\bootstrap\bootstrap.log`：
  - `Recovery: invalid recovery.ini: bootstrap operation failed`
  - `Verified updater failed.`
- 没有任何 Incidents 日志：`App.OnStartup` 的 bootstrap 分支在写日志前执行
  `CanMaintainChapter` → `ChapterUpdatePolicy.IsManaged`；新包有 `DFLegacy.Chapter.json`
  但没有 `.dflegacy\v4\installed.json`，也不存在 checkpoint，`ReadInstalled()` 返回 null，
  于是 `Shutdown(1)`，原生入口只显示失败对话框。
- 旧包另有两处打包缺陷：压缩包多一层 `.tmp\full-client-1.0.17\`；
  `DFLegacy.Bootstrap.ini` 为 205 B（CRLF），与清单的 204 B / `92e2fe66…` 不符。
- 对照实验：只补齐 `client\.dflegacy\v4\installed.json`（manifest 为 `e4da14c2…`）后，
  同一目录即可启动，更新器 `independent-repair` / `repaired-and-verified`，App 1.0.17 登录窗口出现。

## 修复

- 以 `.tmp\full-client-1.0.17` 重新打包 7z：
  - 压缩包根目录直接是游戏目录，不再有 `.tmp\` 嵌套；
  - `client\DFLegacy.Bootstrap.ini` 使用清单一致的 204 B（`92e2fe66…`）；
  - 内置 `client\.dflegacy\v4\installed.json`（433,809 B，`manifestBytes` 为发布清单）、
    `client\.dflegacy\bootstrap\recovery.ini` 和 Updater 恢复副本。
- 新包 `DFLegacy-Chapter2-Full-v1.0.17-r2.7z`，SHA-256
  `16a1863600a76b523f1f33cccf4533c128638240152e5ba1fa5c58533aa3ee14`，1,039,895,875 B。
- 未改动：App/Updater/Diagnostics、V4 清单、`Script.pvf`、服务端镜像、固定入口 `8cfbeb4c…`。

## 验收

- 干净目录 `G:\tmp\pkg-1017-r2-final` 解压运行：
  - `bootstrap.log`：`Verified updater completed.`
  - 更新日志：`stage=independent-repair`、`result=offline-verified`（首启无需联网修复）
  - App 1.0.17.0 登录窗口「地下城与勇士 · 第二章」；`DFLegacy.Bootstrap.ini` `92e2fe66…`。
- 发布后匿名校验：GitCode 7z Range 请求返回 `206`，总长 1,039,895,875；配置资产哈希 `c69756e8…`。
- GitHub `v1.0.17-r2` 与 GitCode `v1.0.17-r2` 各 4 个资产，摘要一致；旧 `v1.0.17` 资产未覆盖。

## 后续

- 完整包必须走种子化打包：至少写入 `.dflegacy/v4/installed.json`、
  `.dflegacy/bootstrap/recovery.ini` 和 Updater 恢复副本（参考
  `tools/release/chapter_package.create_starter`），不要直接压缩 staging 目录。
- 1.0.16 整包存在同一缺陷（无 receipt），已被 r2 取代；1.0.16 安装仍使用原地自动更新，不受影响。

## DFOLauncher 外层入口

- r2 包根目录保留 `DFOLauncher.exe`（454,504 B，v1.0.15，SHA-256
  `63d079486edf60c089c16e986c99df980d056baa7c586a3bb69ccbe14c462439`）。
- 实测：双击根目录 `DFOLauncher.exe` → 启动 `client\DFLegacy.Launcher.exe`（固定入口）→
  校验/修复 → App 1.0.17 登录窗口；首启日志 `Verified updater completed.`，
  再次启动 `Completed receipt opened app.`。DFOLauncher 自身启动后退出。
- `DFOLauncher.exe` 不在 V4 清单内，更新不会生成或删除它；需要时从 r2 包复制到游戏根目录即可。
  它不绕过校验，实际更新检查仍由 `client\DFLegacy.Launcher.exe` 完成。
- 1.0.15 的固定入口是 `94441d8d…`，与 v1.0.17 清单的 `8cfbeb4c…` 不同，仍不能原地升级；
  使用 r2 整包后同时获得 DFOLauncher 与 1.0.17。
