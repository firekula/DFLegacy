# 2026-10-27：ACT1 师徒基础关系验收

本组接通 CMD79 申请、CMD80 接受/拒绝、CMD81 解除、CMD82 名单，以及 NOTI72/73/74/75/77。规则依据为官服 monitor 的 `OnRequestMemberEnter`、`OnMemberEnterReply`、`OnMemberSecede`、`OnCallMemberList`、`IsPossableMemberEnter`、`CheckMemberEnter` 和 `CheckEmptyMember`；ACT1 原生收发函数逐字段核对。官服 monitor SHA256 为 `a099d2b3ebc77bfe1393bec3543a41ba8c20c99d0abc26619241d31964dea6d7`，本地静态证据保留于 `.recon/mentor-20261027/`。

## 官服规则与版本边界

- 按双方当前等级决定身份，高等级为师傅，同级拒绝；师傅至少18级。18–19级可收5人，20–29级8人，30级以上10人。徒弟只有一位师傅，同时可以有自己的徒弟。申请和接受时均重验等级、关系、容量、黑名单和登记限制，并防止等级变化后的关系环。
- 目标必须在线。待决邀请绑定双方当前会话，断线、退出或重新选角清除；不增加未取证的服务端超时。ACT1 原生确认窗约5秒后会自行发送拒绝，本次实际收到了该 CMD80。
- 有关系记录时，上次登记须严格早于最近本地06:00；主动解除须严格早于最近06:00减两天，即第三个日界后允许登记，不能换算成固定72小时。仅主动解除方更新解除时间。
- 当师傅和徒弟都为空时，按 `CheckEmptyMember` 删除关系记录与时间限制，并发送 NOTI75。因此双方彻底为空后可以立即重新结成，本次双客户端已验证。上级ID为0表示未加载，不能推定为“毕业”。
- 初始关系等级1、经验0、下级阈值3，来自 `CMemberExpTbl::GetMemberExpLevel@0806207E`。关系经验增长、COF、经验百分比及疲劳奖励仍未恢复，不写入猜测的奖励数值。官服 `GMAccounts` 与本项目后台管理员权限不等价，不据此增加管理员禁拜师规则。

## ACT1 协议

所有名字使用 `u32 CP936字节数 + 名字`。CMD79/81 的公共序号后为名字，CMD80 后为一个回应字节（1接受、2拒绝），CMD82 只有公共序号；长度、尾随字节、内嵌NUL及非法回应严格拒绝。

| 数据包 | ACT1 body |
| --- | --- |
| CMD79 回应 | `u8成功 + 名字`；失败为 `0 + 名字 + u8错误` |
| NOTI73 邀请 | `u16请求者等级 + 名字` |
| NOTI74 请求者结果 | `u8状态 + u8对方身份 + u8等级 + 名字` |
| CMD80 接受者结果 | `1 + u8对方身份 + u8等级 + 名字`；身份1师傅、2徒弟 |
| CMD81 / NOTI77 | 成功回应为 `1 + 名字`；对方通知只有名字 |
| NOTI75 | 空 body，清除空关系 |
| CMD82 名单 | `1 + 师傅条目 + u8徒弟数 + 各徒弟完整条目` |
| NOTI72 在线状态 | `u8上线/离线 + u8频道 + u8等级 + 名字` |

名单每条包含频道、等级、名字、被对方屏蔽标志、关系等级、当前经验和下级经验。当前单频道为1，离线FF；空师傅全零，空名单18字节。原来误称私人商店轮询的空回包保留兼容别名，实际路由现为师徒名单。

## 持久化与会话安全

沿用徒弟的 `MentorCharacterId` 作为唯一规范边，师傅的徒弟列表从存档派生；可空 `MentorRegistration` 保存时间，兼容旧存档。所有变更在存储锁内从规范状态复制、整档原子保存，提交后才发布结果，保留已有组队金币信用与收据。写入结果不确定时隔离存储，重启按实际快照恢复。

删角和批量替换同事务清理失效边、环与空登记，不给幸存方追加主动解除惩罚。通知在提交后排队，消费时重新读取关系，避免旧的“空关系”通知覆盖期间新建的关系。每次角色会话使用独立FIFO投递队列；退出等待在途发送完成，防止旧邀请、旧回应或旧连接摘除影响新会话。
