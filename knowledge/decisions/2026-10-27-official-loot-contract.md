## 普通 get_item 的完整核心规则

入口 `CParty::get_item@085A3B98`；金币与特殊金币物品1199在普通物品分支之前独立处理。普通物品：

```text
总成员数 <= 1：直接给拾取者，四槽分数0
否则：
  enabled = (map_item.source == 1)
  if rarity > 3: enabled = request.choice == 1
  if source != 0 && epicRouting: enabled = request.choice == 1
  仅 enabled && (rarity > 0 || epicRouting || isAvatar) 才投骰
```

来源不等于1不是永久禁止，后面的高稀有度选择可以覆盖。必须保留 byte，不能退化成一票否决的 CanRoute bool。客户端报告的 RequestedRarity 不作为权威值，模板 rarity 才是门控依据。

候选按槽0..3扫描：成员有效、活人标志896==1、库存只读试算返回非-1。**死亡拾取者**在样本中只记录反作弊，并非整个请求立即拒绝；“死者不参与骰子”不等于“拒绝死者所有直取/宠物拾取请求”。

### 候选预筛与 ACT1 栏位适配

- 快捷槽3..8；使用 ACT1 每分类32格区间9..40、41..72、73..104、105..136，不搬入样本的57/105/153等新版起点。
- 先找快捷栏同ID堆，再找对应分类同ID堆。首个同ID堆若合并超过上限，立即排除，不继续找后面的堆或空格；不拆多堆。
- 叠加默认上限9,999,999；显式0/负值不重解释成无限。整数溢出分支与堆上限失败分开处理。
- 普通装备不叠加，找分类空格再找快捷空格；消耗叠加物的空格搜索为快捷优先。Avatar及Creature保留 ACT1 现有独立栏位适配。
- 不提前检查负重、职业等级、max-having；这些不能从最终入包 planner 偷渡成候选规则。

### 计分、轮转和职业

- 每个候选基础1；轮转候选+40；**仅武器**且 usable-job 位匹配+30；再加 `rand(100-base)`。实际分值最大99。
- usable-job 缺省11位全0；明确职业只置对应位；all及官服加载器未知字符串置全部位。只按基础 job，不按成长、精通或等级。
- 目标为 `last+1`，按**总成员数**回绕；实际候选按压缩序号计数。目标序号不存在时无人+40，last不变，不按剩余候选数重新取模。
- 官服开局随机last；本工程因成员异步入场，将同一随机初始化延至首次需要路由，避免仅登记队长时按人数1初始化。未宣称PRNG序列逐次相同。
- 幸运物主先取89..99；每个候选仍消费其普通随机，再对物主覆盖或将其他人压到物主分以下。物主不绕过资格，缺席时其他人仍受分数上限。生成/扣幸运点及稀疏 map 怪癖另见完整报告。
- 最高分获奖；同当前最高正分时后遇槽显示分减1，先槽保住胜出，不保证所有显示分两两不同。
- 总人数>1而仅一个合格候选时，仍投骰；完全无候选报22，不给拾取者兜底，不摘地面。
- 选中后最终入包失败报4，不重掷。实际入账仍由得主会话完成，保存失败放回原对象。

## ACT1 的真实接口

### CMD46（日志 Body 共8字节）

| 偏移 | 字段 |
|---:|---|
| 0 | u16 transport sequence |
| 2 | u16 groundId |
| 4 | u8 routingChoice；等于1表示本次请求启用分配 |
| 5 | u8 RequestedRarity，客户端模板快照 |
| 6 | u16 guard，客户端15位随机值与原生范围标志的组合 |

普通 helper 从 actor+0x7A0 获取 descriptor，经虚+0x18返回descriptor+8，再读metadata+0x60（设备、叠加物加载复制链均闭合）。**此已核实 helper 分支精确在 rarity==4 开窗**，其它测试值0/1/2/3/5直接发 choice0；不能把这个局部分支泛化为全部角色动作/场景的完整上游条件。

确认窗工厂type98，内部id113；两个发送分支choice0/1，另一按钮只关闭。发送后才加入pending并置actor+0x7A5=1；取消未走发送路径。确认窗guard为 `(rand15 | 0x12) & ~0x20`；普通发送bit1来自原生拾取范围谓词，bit4=1、bit5=0。服务端保留guard，不把它当坐标、物品id或新版校验字段，也不伪造固定值。

### 成功、失败与地面移除

- 物品 NOTI39 固定12字节：`groundId:u16,picker:u16,score[4]:u8,winner:u16,destination:u16`。不加官服较新版尾byte。
- 所有接收端会先停用地面actor；只有winnerUid等于本地uid才移交descriptor并入包。必须先发送完整结果，再发送移除扩展，避免actor先销毁导致结果分支跳过。
- CMD46成功`[1]`是原生空操作，不能取代NOTI39；错误4、21、22均走原生pending恢复，避免“进不了包后再也捡不了”。
- NOTI40用于生成对象，不能伪装删除。NOTI86 subtype5原生无动作；现有IJL15九字节地面编号扩展继续承担直取时队友端移除。骰子全队广播时原生已停用，扩展为幂等补充。
