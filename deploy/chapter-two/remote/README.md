# 第二章域名部署测试版

此配置用于已发布的域名中继测试镜像 `ghcr.io/firekula/dflegacy-chapter-two:v1.0.1`，旧 `v1.0.0` 不支持。按用户要求提供镜像供手动部署测试，没有操作线上服务。真实公网地址切换及直接连接仍未验收，不应表述为全部客户端体验已完全一致。

`C2_SERVER_HOST` 与客户端 `ChapterTwoServerHost` 填相同的 DDNS 域名，不含 `http://`、端口或路径。移除旧 `C2_PUBLIC_IPV4` / `ChapterTwoServerIpv4`，不要同时填写。服务端不需要查询或保存当前公网 IP；监听 `::` 接受两种地址族，IPv4-only 主机可以填 `C2_BIND_HOST=0.0.0.0`。客户端优先 IPv6，入口不可达时尝试其他解析结果，`Relay.Preference=ipv4` 可调整优先级。

每次进入游戏重新解析服务器域名。本次会话固定目标，公网地址变更造成断线后重新登录即可重新解析；操作系统 DNS 缓存和 DDNS 生效时间仍需等待。既有战斗不保证无缝恢复。登录、频道、组队和 PK 使用各实例独立的本机转发，不修改系统 hosts 或 DNS。

商城本地补丁及背景随启动器提供，充值、黑钻提交和账号操作使用服务器域名。连接复用最多 30 秒，不自动重试充值或物品发放。`C2_TEST_CERA_TOP_UP` 是原有测试点券/黑钻开关，默认关闭，按需显式设为 `true`。其余两个开关保留第一章的地区频道与周末双倍疲劳行为。

原生 Linux Podman 使用 `podman compose -f compose.yml --env-file .env config` 检查配置。使用 host 网络，无需添加 `ports`。第二章独占以下玩家端口，宿主机及云防火墙按实际网络开放：

- TCP：7004、7100–7105、7110–7112、42312、47001、47005、48090、48091。
- UDP：42312、47005、47012、47013。

管理器仅监听 `127.0.0.2:${C2_MANAGER_HOST_PORT}`，与玩家入口独立。`C2_DATA_DIR` 为独立第二章存档目录，`C2_PVF_PATH` 为配套服务端资源文件。首次迁移只复制停服备份，不让两章共享可写存档。更新镜像不会替换这些宿主机挂载内容，但服务运行时会正常写入存档，更新前仍应停服备份。

目录、PVF 和配套镜像准备好后执行 `podman compose -f compose.yml --env-file .env up -d`。域名解析指向玩家可达的宿主机；这份示例不包含外部转发辅助容器。完整客户端自动更新仍未发布，须使用本次域名启动器。
