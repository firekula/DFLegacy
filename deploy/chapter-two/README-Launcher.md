# DFLegacy 第二章 Windows x64 启动器

1. 把 `DNFS1C2.zip` 解压到一个新目录。
2. 把启动器 ZIP 的内容解压到这个副本中，确认 `DFLegacy.Chapter2.Launcher.exe`、`DNF.exe` 和 `Script.pvf` 位于同一层。
   本轮同步主分支后的测试包另附第二章资源 ZIP。将其中的 `Script.pvf` 放入同一隔离副本，服务端同时使用本轮配套包内的资源。原版第二章资源也保留启动校验兼容，新增商店和技能内容使用配套新版资源。
3. 从配套服务端包双击 `Start.cmd`，在管理页启动游戏服务。
4. 双击 `DFLegacy.Chapter2.Launcher.exe`。可从界面注册本地账号、登录、选频道和创建角色。双开时再打开一次启动器，并使用另一个账号。

需要 Windows x64 和 Microsoft Visual C++ x64、x86 运行库。启动器使用原始第二章游戏资源，内嵌第二章兼容启动组件，在首次启动时按需展开，保留原版 `DNF.exe` 和 `ijl15.dll`。

商城显示和中文输入法修复已内置在 `DFLegacy.Chapter2.Launcher.exe`。使用中文输入法时，关闭聊天框可直接使用游戏字母键。打开聊天框后仍可输入拼音和选词，也可用输入法本身的快捷键切换中英文。

默认使用同一台电脑的第二章服务，账号和选项保存在独立的 `launcher.chapter2.json`，客户端日志在 `Logs/DFLegacy`。

域名连接版可在该配置中设置 `ChapterTwoServerHost` 为服务器 DDNS 域名（不含 `http://`、端口或路径），移除旧 `ChapterTwoServerIpv4`。服务端使用配套 `ghcr.io/firekula/dflegacy-chapter-two:v1.0.1` 镜像；旧 `v1.0.0` 不支持此配置。参考随包提供的 `launcher.chapter2.domain.example.json`，保留自己的账号与其他设置。每次进入游戏重新解析域名，每个双开实例有独立的本机转发。公网地址改变后需要重新登录，并等待 DDNS 与系统 DNS 缓存生效。商城本地补丁随启动器运行，实际提交使用服务器域名，不会自动重复充值。

普通更新、跨章更新和修复下载统一显示原版金色大更新窗口。安装或恢复游戏资源时仍使用大窗口。备份、替换或恢复启动器自身的可执行文件时会短暂切换为原版绿色小窗口。账号管理、物品工具和性能面板沿用原版边框与控件风格。

第二章现以普通桌面进程启动，与第一章使用相同的用户上下文；仍使用独立客户端目录、独立服务存档，本机模式使用 `127.0.0.2`，域名模式使用每个实例独立的回环地址。每次启动的本地补丁临时文件及原生日志保存在 `Logs/DFLegacy/Sessions` 的独立子目录，退出后将本次原生日志归档到 `Logs/DFLegacy`。启动组件不再创建容器或修改目录权限；缺少新版组件时会明确报错。

启动错误和异常退出会在 `Logs/DFLegacy/Incidents` 保留本地报告。第二章 broker 的独立事件记录在 `chapter-two-events-*.log`，原生上下文在对应的 `chapter-two-client-*.log`。报告记录实际游戏进程的 PID 和退出码，捕获到未处理异常时还会记录异常码、可识别的模块名和相对偏移。正常退出和正常地址重试不生成崩溃报告。

从 v1.0.13 起，运行中的原生启动组件写入 stderr 的警告保留在 `chapter-two-client-*.log`，行首为 `[stderr]`。例如 `libpng warning: iCCP: known incorrect sRGB profile` 会继续记录，启动器依据原生握手和进程退出状态判断启动结果。若进图掉线，提供发生时间、地图、对应的启动日志和故障报告编号，便于核对掉线与后续启动失败发生在哪一阶段。

配套服务端在暗精灵墓地由全队共享四个陵墓守卫击杀。提前离开深渊房后，仍存活的陵墓守卫可以回来继续打，深渊敌人可以跳过。服务端确认第四次守卫击杀后为全队开放 Boss 门。

配置远程服务器时，登录器按当前 Windows 用户的诊断设置向该服务器上传脱敏报告，管理员可在「客户端故障」查看。发送暂时失败时，登录器保留待发送报告并在后续启动重试。本机测试只写本地日志。完整日志、聊天内容和原始内存留在本机。

需要增加原生调试输出时，用 `DFLegacy.Chapter2.Launcher.exe --detailed-crash-capture` 启动本次会话；默认关闭。第二章复用已有 broker 的详细记录，不启动另一个调试器，也不自动生成内存转储。详细日志可能包含内存片段，仅保存在本地；排查后可直接退出启动器，再正常启动。

游戏画面显示 FPS 和私有提交内存。复现进图卡顿时可记录地图、发生时间和使用的画质选项。

在游戏窗口按 Ctrl+F10 可打开或收起独立的 Debug 性能面板，可拖到游戏窗口外或另一块屏幕。面板显示最近 600 帧的间隔、P95/P99、慢帧和近两分钟的内存变化，底部显示全程累计。切出游戏会暂停帧采样，回到游戏后继续。收起面板时，日志继续记录。

`Logs/DFLegacy/chapter-two-perf-*-interval.csv` 每约 2 秒记录一段，`chapter-two-perf-*-total.csv` 同步追加累计统计，最后一行是最近保存的累计结果。时间列使用 UTC，可与服务端日志按时间对照。帧时间记录 33.3、50、90 ms 阈值计数，CSV 中的 P95/P99 使用 1 ms 桶的上界，500 ms 以上的百分位用该段最慢帧作上界。私有提交和工作集每秒取样一次，记录起点、最新值、最低值、均值和峰值。游戏退出时，文件保留到最近一次写入。

`chapter-two-perf-*-slowframes.csv` 逐条记录达到 50 ms 的前台帧。资源计时覆盖动画查找、动画加载、IMG 加载和脚本加载，特效计时覆盖星弹生成和已定位的击打、暴击分支。嵌套耗时归入实际执行的部分。画面提交列记录 CPU 等待原生 Present 返回的耗时，剩余时间列记录这些入口之外的时间。使用 `trace_complete=1` 的行做归因。原生分辨率和增强缩放共用该画面提交入口。

键盘诊断列分别记录消息队列、字符转换、按键和输入法消息处理、DirectInput 读键以及兼容层合并键状态的耗时。只保存字母键和方向键的按下次数及文字消息次数。复测时可以在城镇空闲、点按未绑定字母键、点按方向键各留一段。商城处理和 D3D EndScene 单独计时，便于比较商城道具页和装扮页静置时的长帧。

本轮增加拾取后保留当前背包页，手动点击背包分类继续使用原生行为。启动器的账号配置保存沿用主分支的并发更新保护，并保留新版本增加的未知配置字段。

测试商城前，在服务端 GUI 开启「本机测试充值」并重启。充值和黑钻继续使用游戏原生网页窗口，页面取自启动器的本机站点，游戏内背景随窗口尺寸对齐。

在「游戏设置」的「游戏显示」页可以切换渲染器。发行客户端默认使用 Direct3D 11。切换到 Direct3D 8 后，保存并重新启动游戏即可生效。

同一页可以调整 NPC 对白正文的字号和行距。字号可选 12、14、16、18，行距可选 0 至 4 像素，默认字号 16、行距 3。

游戏内的声音和画面选项保存在本客户端 `.dflegacy/chapter-two/settings/DNF_CHINA.cfg`。首次启动新版会采用本目录最近一次有效会话的设置，之后重开不再重置。按键继续使用游戏原有的 `.keyset` 文件；不要清理这些文件或整个 `.dflegacy` 目录。

启用第二章调试模式时，Ctrl+F11 物品工具内提供「测试静音（仅当前游戏）」，默认开启，无需登录 GM 即可切换。它只将当前游戏进程的音量设为零，不修改系统总音量或游戏保存的音量滑块；取消后恢复本次游戏原音量。选择会保留，普通非调试模式不自动静音。

打开城镇小地图后，可以右键点击当前区域内的可走地面。任务图标盖住地面时也可以选点，方向键可以打断自动移动。

在服务管理器启用本机测试充值并重启游戏服务后，可从启动器的「更多服务」或管理器的「运行概览」打开测试点券和黑钻页面。游戏运行时也可以通过管理器打开。

带显示预览的构建可在「游戏设置」里试用第一章的锐利、点采样或线性缩放。默认使用原始 640×480。画质、鼠标点选和设备恢复需要手动验收。遇到问题时切回「旧版兼容」，重新启动游戏。
