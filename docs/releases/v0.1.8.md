# v0.1.8 发布与升级

本版服务器使用 `ghcr.io/firekula/dflegacy:v0.1.8`（linux/amd64、linux/arm64）。客户端在 GitHub `firekula/DFLegacy` 的 `v0.1.8` Release 按 x86/x64、normal/test 分发。Gitea 同步源码；不更新在线容器或账号数据，不自动构建独立 Windows/Linux/macOS 服务端。

## 客户端升级

- 已有 v0.1.6：首次安装 `DFLegacy-client-update-v3[-test]-win-{x64,x86}.zip` 兼容包，重启登录器后完成 V4 迁移。这些兼容包只包含旧版能解析的登录器、补丁、PVF（测试版另有 debug.dll）；不能直接把新增诊断助手加入旧清单。
- `DFLegacy-bootstrap-v0.1.8-{x64,x86}-{normal,test}.zip` 包含固定启动入口、登录界面、独立更新程序及恢复副本；直接覆盖前先退出游戏并备份，保留 `launcher.json`、`Config.ini`。不要混用架构或漏复制隐藏的 `.dflegacy` 目录。
- 完整整合包包含游戏资源和最新 PVF，适用于旧客户端或网络较慢的用户；建议解压到新目录，再迁移自己的账号和窗口配置。可继续双击 `DFLegacy.Launcher.exe`。
- 每次启动校验全部受管理文件，缺失或损坏只下载对应内容；下载断点、安装事务恢复及配置迁移沿用 [V4 合同](../../CLIENT_UPDATES_V4.md)。原生入口自身损坏或全部恢复程序都丢失时，重新解压对应修复包。
- 公开 GitHub 更新配置为 `UpdateProvider=github`、`UpdateChannel=stable`、`UpdateRepository=firekula/DFLegacy`、`UpdateServiceUrl=""`、`DisableGitHubUpdates=false`。正式包不包含 Gitea 测试源或 probe 资源。

## 服务端升级

更新 `.env` 中的 `DFLEGACY_IMAGE=ghcr.io/firekula/dflegacy:v0.1.8`，然后在原 Compose 目录执行 `podman compose pull`、`podman compose up -d`。保留 `dflegacy-data:/app/data`，不要删除数据卷。18080/18081/18082 原访问方式不变，不需要开放 18083。

若尚未部署四类决斗频道，在现有端口列表增加 `7110-7112:7110-7112/tcp`，并放行服务器防火墙对应 TCP。保留原有游戏端口、`DFLegacy__Channel__RegionalChannelsEnabled` 与测试充值设置。

新版 PVF SHA256：`69aa1a0338408fbcc3eff381924311ba42119a2cd2db4e8ffd2fab369bb9b34b`。客户端更新自带该文件；服务器在 18080 部署管理页停止游戏服务后上传并选用同一份 PVF，再保存、启动。镜像升级不会替换持久卷内选中的 PVF。不要只更新客户端导致商店、频道表与服务器不一致。

## 内容与验证范围

含 v0.1.7 决斗频道、组队战/擂台赛、GM 胜点与全服邮件，以及本版 GM 脚本修复、Boss 结算后禁止非法换房、单人“牛来”归拢掉落、逐文件更新与自动基本故障报告。诊断使用现有 8081 接收和 18081 GM 查看，不新增公网管理口；原始转储只留本地。

赛丽亚 PVF 在上一版 `c2321f05…` 上仅修改 `itemshop/equipmentshop7.shp`，原 98 个位置保持，追加 201 个有正原价材料并补齐七列；63 个无价格材料暂不出售。48,327 个条目独立比较，其他条目字节不变。原始 Win7/Win10 偶发崩溃不因增加诊断就视为已修复，具体实机验证边界见既有验收报告。

## 发布者检查

1. 固定源码提交；构建优化原生模块、两架构自包含程序，生产符号只私有保留。
2. 生成四个 V3 兼容包时使用 `build-client-packages --updates-only --legacy-bridge --script-pvf <path>`。V4 的 `bootstrap_package` 参数必须显式指定 GitHub/stable/https://github.com，保留独立 Gitea 测试源默认值。
3. V4 与 V3、修复包在同一 GitHub 草稿中完成完整资产校验后公开；不覆盖既有正式标签，不把私有 Git 历史推到 GitHub。
4. 验证镜像两架构、容器冒烟、公开匿名资产摘要、安装清单及整合包隐私排除。发布回执保留最终版本、源码、各文件 SHA256 和镜像 digest。
