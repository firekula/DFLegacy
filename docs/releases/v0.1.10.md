# v0.1.10 更新与部署

服务端镜像：`ghcr.io/firekula/dflegacy:v0.1.10`，目标平台为 linux/amd64、linux/arm64。客户端使用 GitHub `firekula/DFLegacy` 的同名 Release，保持 x86/x64、normal/test 四路独立更新。Gitea 只同步代码，不发布本轮镜像或客户端附件。发布过程不操作在线容器、存档或奖励；产物可用性以 Release 和镜像回执为准。

## 本版内容

- 修复冰心少年第二房间的共用文字绘制生命周期崩溃，以及通关清场误杀冰之心。
- 登录器复用完成校验记录，普通启动直接打开登录界面，不再先等待网络或弹验证窗口。后台发现新版并下载后，交回独立更新程序安装。显式修复和进入游戏的完整校验仍保留。
- GM 邮件最多十格独立物品 ID／数量。原版每封只能携带一个物品，因此自动拆信；每位角色金币只发一次。支持单角色和全服、原子保存、群发恢复及失败补发。
- 43 个副本的资源与房间生成排查未发现新的同类配置错误；这不等于每张图的所有技能和组队情况均已实机测试。深渊流程未改。

测试证据和已知限制见[图文报告](../acceptance/2026-11-10-v0110-hotfix-mail.md)。

## 服务器

在原 Compose 目录将 `.env` 中镜像改为：

```dotenv
DFLEGACY_IMAGE=ghcr.io/firekula/dflegacy:v0.1.10
```

然后执行：

```bash
podman compose pull
podman compose up -d
podman inspect --format '{{ index .Config.Labels "org.opencontainers.image.version" }}' dflegacy_dflegacy_1
podman logs --tail 80 dflegacy_dflegacy_1
```

保留 `dflegacy-data:/app/data` 数据卷和现有环境变量；不需要增加端口，不需要 18083 更新服务。已有四类决斗频道仍需原来的 7110–7112/TCP 映射和防火墙规则。部署管理、GM 和玩家中心访问方法不变。

本轮 PVF 没有修改。v0.1.8 正式 PVF SHA256 为 `69aa1a0338408fbcc3eff381924311ba42119a2cd2db4e8ffd2fab369bb9b34b`，服务器已经使用该文件就不必重新上传。旧版服务器若仍选用更早 PVF，应停止游戏服务后在 18080 上传同一份 `Script.pvf` 并选用。镜像不会覆盖持久卷内的 PVF。

## 客户端

已有 v0.1.8 保持 GitHub/stable 更新源，退出游戏后打开原图标完成升级；首次建立新校验记录需要一次完整验证。V4 序列 2 保留 v0.1.8 固定入口的原始字节，不替换固定入口，不需要修改快捷方式。源码中的新原生快速入口实验不随本版交付。

下载失败或需离线替换时，选对应的 `DFLegacy-bootstrap-v0.1.10-{x86,x64}-{normal,test}.zip`。关闭游戏和启动器，先备份，再完整解压到游戏目录，包含隐藏的 `.dflegacy`；保留自己的 `launcher.json` 和 `Config.ini`，不要混装架构或漏复制文件。修复包含补丁、PVF 和更新组件，不含完整原版游戏资源。

旧 V3 客户端使用同 Release 的 `DFLegacy-client-update-v3[-test]-win-{x64,x86}.zip` 过渡包，重启后迁移至 V4。正式配置为 `UpdateProvider=github`、`UpdateRepository=firekula/DFLegacy`、`UpdateChannel=stable`、空 `UpdateServiceUrl`，不要使用 Gitea 测试源。

V4 安装完成后，可以在客户端目录查看实际安装版本：

```powershell
(Get-Content -LiteralPath .\.dflegacy\v4\installed.json -Raw | ConvertFrom-Json).release.tag
```

## 构建与发布约束

先固定私有源码提交，再向 GitHub 同步净化后的源码快照，不推私有 Git 历史。原生生产 PE/PDB 配对私有保留，发布附件不得含符号、存档、账号或测试配置。四路 V4 资源、四个 V3 过渡包和四个修复包在同一 GitHub 草稿完整校验后公开；已有 v0.1.8 标签不可覆盖。Docker 内嵌同批新 client-assets，不自动构建独立 Windows/Linux/macOS 服务端。
