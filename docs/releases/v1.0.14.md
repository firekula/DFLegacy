# 第二章 v1.0.14

## 客户端

- 商城「道具」页新增 **+10 装备强化券**：商品号 `100001`，物品 `7274`，数量 1，价格 100 塞拉。商城目录行写入客户端 `Script.pvf` 与服务端配套 PVF 的 `etc/newcashshop.etc` `[item]` 段，客户端和服务端使用同一行，避免只在一侧上架。
- 强化券使用入口：右键强化券 → 选择装备 → 确认。服务端消耗 **1 张**券，把目标装备的强化等级直接设为该券的等级（`7273`=+7、`7274`=+10、`7275`=+12），**不消耗材料或金币，不做失败判定**，也不会因为目标已有更高强化等级而拒绝覆盖。
- 客户端 `Script.pvf` 已更新，SHA-256 为 `1c7f01da1aaf982760ea3908fa403aefd088e6b7116c0ca5ddce7f33e77ea84d`；登录器同时保留旧 PVF 哈希的兼容条目，但新商城行只有配套新 PVF 才有。完整整合包和更新包必须使用配套 PVF。
- F11 调试面板的“右键传送”和“无敌”仅存在于调试构建：正式 host 不定义 `DFL_CHAPTER_TWO_DEBUG_CONTROL`，正式 `launcher.chapter2.json` 使用 `ChapterTwoDebugEnabled=false`，不会创建调试共享内存，也不会显示调试面板。

本版固定入口、托管登录器和更新器的文件版本统一为 `1.0.14`。推荐玩家直接使用完整整合包替换整个游戏目录；账号和游戏选项保存在独立 `launcher.chapter2.json`，升级不会清除。使用登录器增量更新的玩家需要确保拿到与本版配套的 `Script.pvf`，否则商城不会出现新商品。

## 服务端

- 协议 83（装备强化请求）接入服务端 `EquipmentReinforcementPlanner`：校验目标装备、券数量和券类型，按券等级直接设置 `State` 的低 5 位；只扣一张券，不读 PVF 材料/金币，不触发随机失败。
- 服务端配套 `Script.pvf` 的商城目录包含同一行 `100001 7274 1 0 0 100` `+10 Ticket` `0 0`；服务端镜像本身不内置 PVF，部署时仍需把配套服务端 PVF 放到持久化资源目录。
- 配套镜像标签：`ghcr.io/firekula/dflegacy-chapter-two:v1.0.14`。

## 升级与整合包

- **完整整合包**：包含游戏客户端、正式登录器、配套客户端 `Script.pvf` 和正式连接配置，解压后直接替换整个游戏目录，不需要逐级升级。
- **登录器包**：只包含正式登录器和说明，适合已有完整客户端且已拿到配套 PVF 的玩家。
- 服务器：更新镜像后保留原持久卷；替换配套服务端 PVF，重启游戏服务。

## 验证范围

- 用户实机确认（调试/本地测试构建）：F11 面板右键传送、商城充值页面、副本无敌、商城 +10 强化券上架/购买流程通过。
- 自动化：服务端构建、仓库 smoke 测试、第二章原生测试、登录器发布构建和 PVF 逐条目校验。
- **未验证**：正式发布包的真机启动/商城/强化结果；GitHub/GitCode 附件上传；镜像推送。按用户要求，在确认万无一失前不执行真实上传。

## 已知限制

- 商城中的 +10 券显示为商品条目，强化等级由服务端在购买/使用时处理；商店列表本身不显示“+10”字样。
- 调试面板传送/无敌是调试客户端功能，不是正式客户端功能；正式包不应出现 F11 调试入口。
- 服务端镜像不包含 PVF 和存档；部署方必须使用配套服务端 PVF，并保留原数据卷。
- 本地测试账号、Cera 余额、测试服务器地址和调试共享内存只属于测试环境，不进入正式包。
