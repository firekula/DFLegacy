# 客户端本地事故报告

报告保存在客户端的 `Logs/DFLegacy/Incidents/`，默认不上传。文件名包含本地时间（毫秒）、进程 ID 与事件 ID。`launcher.log` 保留主日志，达到 2 MiB 后轮换为 `launcher.previous.log`。

| 前缀 | 含义 |
| --- | --- |
| `error-` | 启动、配置、账号请求异常或更新失败 |
| `networkerror-` | 结构化中继连接/绑定错误，或通过指令签名验证的 ACT1 原生网络失败提示 |
| `crash-` | 未处理异常链现场，或进程非零退出；通过 `evidence` 区分证据类型 |
| `update-` | 校验、下载和安装摘要；失败的 error 文件引用相同 `updateId` |

每份报告带会话/事件 ID、版本及 commit（构建版本或启动清单身份）、架构、安装目录、带时区时间和阶段。服务端没有提供版本接口时标为 `unknown`。启动器保存最近 64 条经过脱敏的上下文；不保存请求体。账号、密码、令牌、Authorization、URL 查询参数等会被删除或替换。网络报告保存连接 ID、方向、端口、耗时、收发量及 Socket 错误；原生提示入口没有这些数值时写 `unknown`，不伪造统计。

启动器报告最多保留 100 份 / 16 MiB / 14 天；重复事件在一分钟内合并计数，中继重连不会仅因连接 ID 改变而生成新事故。普通报告限制 64 KiB，更新报告最多 4 MiB，每次更新最多保存 4096 条逐文件结果，超限明确记录省略/截断。普通 426 个资源的安装会保留每项结果。原生启动时清理自身旧 crash/networkerror 文件至 64 份 / 4 MiB / 14 天，每进程最多新增 16 类网络报告及一份终止现场，同类网络报告合并最多 1000 次。详细 DMP 使用独立限制。

## 原生语义与证据范围

ACT1 静态样本 SHA256：`6b4850beaf67ec61adb04ae17f119f16278dd05e97b8ffca871a9bdb547de0d5`。仅以只读方式分析，未运行或修改样本。

- 原生事件分发函数 `0x008B2880` 使用 `lParam` 低字作为网络事件，高字为 Socket 错误。
- `0x008B2B5A` 调用原提示函数 `0x00799EF0`，所在分支是 FD_CONNECT 且高字错误非零。
- `0x008B2CF7` 调用同一提示函数，所在 FD_CLOSE 分支仅在原生提示文本非空时执行。场景 5 的正常频道切换使用空消息并绕过此处。
- 安装前验证 x86 PE 身份、首选基址、函数栈帧、条件分支、两处完整 CALL 与提示函数入口签名。两处均通过才写入；失败恢复原字节。跳板保存寄存器/标志并继续原调用，不修改断线或提示行为。原生直连和经本地中继的游戏都经过这一边界。
- 原生未处理异常过滤器记录异常地址/代码、寄存器、模块/偏移与最多 32 个返回地址，不写原始栈内容。保留此前过滤器的处理结果，不把可处理的 SEH 探针记成崩溃、不吞异常。
- 异常退出只有退出码时，报告明确写 `abnormal-process-exit` 和 `nativeCause=unknown`；同会话/进程的原生记录存在时关联该记录。正常退出和取消不生成 crash。EOF、主机停止、成功连接及静默频道切换不生成 networkerror。

**尚未覆盖的默认捕获边界：** 游戏可能在启动后替换异常过滤器，或者既有 CrashSender 处理器在返回前显示弹窗并保持进程存活；本轮没有验证该 CrashSender 专用入口。普通过滤器不能保证捕获栈耗尽、堆严重损坏、强制终止或被替换的过滤链。不存在现场时只作诚实的退出报告，不能宣称这些情况已被默认捕获。

## 显式详细崩溃采集

将单独构建的 `DFLegacy.CrashCapture.exe` 放在登录器旁的 `Diagnostics/` 子目录，用 `--detailed-crash-capture` 启动登录器。只有该参数才会对本次创建的游戏进程启动独立采集进程，普通启动不附加调试器。

详细证据保存到 `Logs/DFLegacy/Incidents/Detailed/<时间-PID-ID>/`。工具保存最近 16 个 DMP，每个限制约 64 MiB / 5 秒（受 DbgHelp 回调粒度限制），异常文本也轮换。游戏退出时自动停止；在该报告目录创建 `STOP` 文件可主动脱离，工具不会因自身退出杀死游戏。此目录中的 DMP 包含进程内存，应只私下交给维护者，勿公开上传。登录器最多保留两次 Detailed 会话（约 2 GiB 的 DMP 预算）；第三次会明确拒绝采集，提示先备份并清理旧目录。不会自动删除仍需反馈的证据。

也可继续使用 [独立诊断包说明](../tools/debug/crash_capture/README.md) 的显式附加与弹窗后快照入口。首次机会异常转储只表示观察到异常，不能单凭 DMP 认定崩溃。

## 本轮验证

- 启动器 IncidentTests：唯一命名、并发、脱敏、计数/容量保留、重复重连合并、更新成功与失败关联、426 个逐文件结果、主日志轮换、取消/EOF/频道切换抑制、未知退出与同会话原生关联、详细采集 opt-in。
- 中继测试使用真实回环 TCP：分片双向/半关闭、RST、连接拒绝、停止、并发与日志回调故障；结构化字段与实际字节统计一致。
- 原生独立子进程：真实 AV、handled SEH、既有异常过滤器、中文路径；已安装跳板的返回值与 callee 清栈；错误 PE、错误分支与错误栈帧均不改写代码。
- 外部采集独立子进程：handled/unhandled AV、主动脱离后存活、事后快照与 16 个 DMP 循环保留。

原生网络测试验证了静态语义、签名与跳板执行，尚未把这些结果冒充真实游戏在线重连/掉线验收。所有自动异常测试仅启动测试自身创建的进程，没有附加现有游戏。
