## 交付行为

1. 部分启动失败会释放本次已经绑定的 TCP/UDP 端口并回收自己的子进程；全部必要监听及私有管理通道就绪后才显示运行中。管理员可以修正配置后直接重试。日志区分端口占用、拒绝访问，并保留经过脱敏的底层启动错误；不终止外部占用进程。
2. 管理员从服务配置页上传 PVF，显示进度，上限 1 GiB，流式写入持久化数据的 `resources/`。解密索引并检查每个文件的路径长度和数据边界。损坏、截断、取消或配置提交失败均保留旧资源与配置；运行中和环境变量控制的资源不能替换。上传不丢失页面上尚未保存的其他配置。
3. 掉落概率用倍数显示：1 倍对应 JSON 的 `Drop.RatePercent=100`，沿用 PVF 基础概率；2 倍表示基础概率乘 2，最高仍为 100%，不表示全部物品必掉。普通怪物/深渊额外倍率重叠时相乘，不表示金币数量。掉落算法未改变。
4. 客户端分发统一为一个 ZIP，直接解压到 `DNF.exe` 所在目录。实际默认包有 6 个文件：单文件 `DFLegacy.Launcher.exe`、`ijl15.dll`、空凭据 `launcher.json`、条款、README 和 SHA256SUMS。`ClientPath=DNF.exe`，`StartServer=false`。默认 INI 内嵌，仅在缺少时创建，已有窗口设置保留。
5. 常用托管进程为两个独立单文件程序：Manager 和 Server。高级手动部署的 Channel 也单独打包为单文件。网页、模板、玩家资源及持久化数据继续独立保存。远端 Windows 归档除客户端资源外没有散装 DLL；.NET 首次运行仍可将内嵌原生依赖解压到私有缓存，Docker 使用数据卷内的 `.net`。

部署指南、README 与包内资源提示已同步更新，具体使用见 [部署管理器说明](../../../DEPLOYMENT_MANAGER.md) 和 [部署指南](../../../DEPLOYING.md)。默认 Compose 不要求宿主 PVF 路径；同版 `compose.pvf.yaml` 提供显式只读挂载兼容方式。

## 门禁发现与修复

独立复核发现两项 Important：PVF 只检查头部会接受损坏索引/截断数据；旧散装登录器校验分支会放过缺少导出依赖的程序。两项均先通过回归复现，再修复并通过全套相关检查。生产发行校验始终要求实际单文件 bundle，没有测试专用绕过。无遗留 Minor。

首轮流水线 8 的原生 `debug_overlay` 失败阻止了发布；旧命令未输出断言。已用真实失败 CTest 夹具证明诊断缺失并补充失败输出，保留失败退出码；相同原生代码本地通过，流水线 9 和最终 11 的 13 项也全部通过。本轮不声称已经查明或修复首轮原生偶发失败。

流水线 9 的全量 Python 又发现导航测试夹具后台线程读取刚发布命令时遭 Windows 短暂 PermissionError，导致线程退出和响应超时。两条错误注入回归稳定复现失败；夹具现对文件不存在/短暂拒绝读取作有界等待，持续失败仍抛错，原有导航断言不变。导航 31 项及最终 CI 全量检查通过，没有修改生产导航行为。流水线 10 为同步旧操作说明而主动取消，没有发布。

## 取舍与验证边界

1. 完整业务冒烟集中到最终集成/CI，而不在每个子任务重复运行；代价是无关回归更晚暴露。最终 Windows/Linux 完整冒烟均已实际通过，发布门禁未减弱。
2. Linux 容器和五目标包验收也集中在最终实际 CI，减少重复交叉构建；代价是平台问题可能在集成阶段才发现。最终归档和 Docker 生命周期均已通过。
3. 历史成功上传的 PVF 保留供配置备份回退，磁盘占用会随不同内容上传增长。清理前须检查当前配置和需要保留的备份引用。
4. macOS/ARM 只有交叉构建与结构验证；没有对应原生机器，仍需目标硬件验收。Windows/Linux 自动检查及合成 PVF 启停不等于真实游戏客户端登录、进图或长期联机验收。

本机当前 TCP 2311 仍位于 Windows 排除区间 2280–2379，绑定可能报 10013；这不是残留游戏进程占用。测试新版时将登录 TCP 端口改为可用端口，并重新导出玩家连接配置。系统保留规则未被修改。
