## 交付行为

登录器设置增加独立的游戏显示页，提供 640×480、800×600、960×720、1024×768、1280×960、1600×1200 和清晰平滑、像素、平滑、兼容模式。保存后下次启动生效。游戏内部保持 640×480，沿用 D3D8，清晰平滑先做整数倍最近邻放大，再做最终尺寸双线性缩放；800×600 的中间尺寸为 1280×960，整数目标直接采用像素放大。

只保存 Width、Height、PresentationFilter，保留其他配置字节。已有配置缺少新键时保留兼容行为，新建默认配置采用 800×600 清晰平滑。显示目标同时核对已保存、当前缓存、编辑框及加载快照中的客户端路径；保存期间持有配置存储只读共享租约。最近运行结果明确标记时间、PID、历史记录和回退原因。

## 明确裁定与代价

以下是已接受的范围和实现裁定，不是尚待修复的 Minor：

| 裁定 | 原因和边界代价 |
|---|---|
| 拒绝原生 API 不可读的编码与首行 BOM 节 | 避免虚假保存成功；用户需先转换该类文件 |
| 互斥、字节检查及原子替换 | 无法对最后检查到替换间的不合作外部写入提供绝对 CAS；该窄窗口可能丢失外部修改 |
| 先保存可读 launcher.json，保存期间持只读共享租约 | 确保写入真实已保存目标；首次需先保存连接，同时连接保存可能短暂遇到共享冲突 |
| presenter 接收调用者表面，hook 持有输出链；拆出共享 hook 模块 | 生产与 GPU/假 COM 测试使用同一路径；增加内部模块，没有新增分发 DLL |
| 有界保留运行时私有虚表尾部，最多 512 项 | 本机 Clear 使用私有槽 133；依赖已验证运行时布局，不保证任意驱动/恶意映像兼容 |
| 在原 COM 调用期间恢复原对象虚表身份 | 兼容既有 WIN7RTM AppHelp；依赖该客户端串行 D3D 调用，并发调用可能绕过 hook |
| 在原映像/指令检查下按名称查找 Direct3DCreate8 导入 | 实测兼容展开客户端迁移了 IAT；无名/序号导入不猜测，需要另行适配 |
| 增强模式换算输入坐标 | 修复实测已有缩放鼠标偏移；未知输入 hook 的组合仍有限制，兼容模式保留旧偏移行为 |
| 全屏、不支持尺寸、DPI 虚拟化可见回退 | 避免二次系统拉伸被误报为增强成功；这些环境不提供增强效果，未修改系统兼容/显示设置 |
| 活跃 BeginStateBlock 录制未覆盖 | 活跃 BeginScene 是不同情形；没有据此推断缺陷，特殊录制客户端仍未验证 |
| 性能限于启动/菜单 CPU 样本和当前 DPI | 不保证战斗、GPU 执行时间或其他显示缩放比例 |
| 原有 IAT 写后失败、连接存储事务边界保留 | 本次修复新增显示目标权威性，不额外认证原有辅助函数/连接存储事务 |
| 一次独立代码复核在发布前执行 | 复核员未重复 UI 操作；视觉证据来自一名操作员，远程产物另行通过明确发布校验 |
