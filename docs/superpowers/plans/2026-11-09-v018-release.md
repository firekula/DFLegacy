# v0.1.8 release plan

User authorization: publish the server Docker image and official client updates, and produce complete offline client bundles. Do not deploy to the online server, modify the original game directory, or disturb Chapter 2 work.

## Constraints

- Gitea receives private source; GitHub receives a sanitized public source snapshot and official client assets. Never push private history to GitHub.
- Version v0.1.8; GHCR linux/amd64 and linux/arm64; client x86/x64 normal/test. No standalone server OS packages.
- Ship the verified Seria PVF SHA256 `69aa1a0338408fbcc3eff381924311ba42119a2cd2db4e8ffd2fab369bb9b34b`: 201 priced materials added, 63 unpriced materials deferred.
- Build on C: and package full clients on G: because D: has little free space. Exclude player data, logs, secrets, dumps, PDBs and test-only configuration.

## Tasks

1. Add tested GitHub stable support to bootstrap packaging and an explicit V3 compatibility bridge excluding diagnostic helper files rejected by the v0.1.6 parser. Preserve the existing Gitea test source boundary.
2. Update release documentation, verify tests, commit an immutable source revision. Export a clean source tree; build native and managed production binaries and retain private matching symbols.
3. Generate four V3 bridges, four V4 manifests and four standalone repair starters including the PVF. Validate old-client migration and each managed file's hashes. Build and smoke-test both server image architectures.
4. Package clean complete normal clients for x86/x64 from the original game files plus new starter resources; preserve user configuration on replacement and verify archives.
5. Obtain one fresh final review. Push Gitea source and sanitized GitHub snapshot, publish an atomic GitHub draft release containing compatibility and V4 assets, and publish the GHCR image. Verify anonymous downloads/pulls and report exact artifacts and deployment commands.

## Acceptance

- Existing V3 clients can obtain the bridge and transition to V4; fresh starter installs have a complete trusted receipt and recovery updater.
- Every published artifact has v0.1.8/source provenance and matches its manifest. No Gitea test endpoint or test probe asset in official packages.
- All release assets are verified before making the draft public. Full offline clients are delivered locally; online runtime and original client remain untouched.
