# Web 管理体验与精简发行包

日期：2026-10-30。基线：`ac08b0a`。状态：独立技术复核完成；用户已确认直接实施、测试并发布新版。

## 需求与已选择的方案

根据本轮实际使用反馈，改善失败恢复、资源上传、倍率说明、玩家包安装和发行文件数量。继续使用已有 .NET 10 管理器、游戏服务、WPF 登录器与共享 Web UI，保留已有游戏内小尺寸页面、客户端补丁行为和存档。

服务端方案已由用户选择：保留独立管理器与游戏进程，两个程序分别自包含、单文件发布。与合并成一个支持双模式的程序相比，这保留现有停服后可管理的结构，改动和回归范围较小。保留当前散装运行时虽然改动最少，但不符合减少文件的诉求，因此不采用。

## 1. 启动、失败和重试

- 已读取本机 Release 日志：一次 PVF 路径不存在，两次 `127.0.0.1:2311/tcp` 无法绑定；当时无游戏进程或该端口监听。真实绑定复现 Windows 错误 10013，`netsh` 显示 TCP 2280–2379 为系统保留范围，UDP 2311 可绑定。因此这几次失败不能归因为本次启动的残留进程。
- 区分地址占用与系统拒绝绑定，标明协议、地址、端口和原始错误原因；Windows 保留端口给出修改对应配置的操作建议。不终止外部进程、不删除系统端口保留规则、不静默修改已有端口。
- 所有启用的必要监听服务就绪后才显示运行中；HTTP 管理通道可访问本身不再代表全部就绪。启用项绑定失败、就绪超时或取消时，停止本次拥有的整个游戏进程树、等待退出并回收状态；保留首个错误与日志，允许直接重试。
- 修复监听器在部分绑定成功、后续绑定失败时的清理边界。增加真实进程/套接字回归：故意令后续服务失败，确认已启动监听释放；撤销冲突后同一管理器可重试成功。管理器保持在线。

## 2. 上传 Script.pvf

- 普通配置页改为选择文件、上传进度、当前资源状态和替换操作，无需管理员输入服务器路径。上传成功自动关联服务配置；兼容已有路径以及 Docker 环境变量指定的只读挂载，挂载控制时说明由部署环境管理。
- 只允许已登录管理员通过现有同源和 CSRF 检查上传。采用流式接收、单任务并发限制、1 GiB 上限（实施选择）；不把整个请求或 PVF 读入管理器内存。资源写入数据目录，与安装目录分离并随数据卷持久保存。
- 固定由服务端选择保存位置，不使用客户端文件名作为路径；检查 PVF 签名及基本长度/结构。用临时文件与原子提交，失败、取消、超限或配置提交失败不破坏旧资源和旧配置。不得覆盖管理员自行挂载的文件。
- 运行中禁止替换，并明确提示先停服；通过同一生命周期互斥门防止上传与启服竞态。PVF 不进入玩家 ZIP、日志或 Release。

## 3. 倍率含义

- 保留现有游戏计算规则和已有 JSON 配置含义。界面将 `Drop.RatePercent / 100` 显示为“掉落概率倍率”，默认 1，2 表示在适用的 PVF 掉落概率上乘 2，概率上限仍为 100%。不表示掉落全部物品，也不扩大掉落表。
- 根据实际引用明确 `Drop.EconomicRate` 的作用范围（怪物普通掉落、深渊等已有判定），避免把它称为金币数量倍率。显示默认值与适用范围，并说明两个设置在重叠判定中会相乘。
- 怪物经验、通关经验同样标明“1 = 原始倍率”，保存后明确提示重启生效。

## 4. 一个玩家 ZIP，解压到游戏根目录

- 普通分发页只有“生成玩家客户端包”。ZIP 根目录直接包含 `DFLegacy.Launcher.exe`、`ijl15.dll`、空凭据的 `launcher.json` 以及必要说明/摘要，不再放入额外 `DFLegacyLauncher` 目录。`ClientPath` 为当前目录的 `DNF.exe`，远程包保持 `StartServer=false`。
- 登录器程序与 .NET/WPF 依赖打为一个自包含 EXE；原生游戏补丁 `ijl15.dll` 必须位于 `DNF.exe` 旁，不能取消。保留需管理员/玩家编辑的少量配置和条款文件，程序可在首次运行产生自己的数据文件；不承诺整个客户端补丁 ZIP 只有一个文件。
- 默认 INI 模板内嵌到登录器，ZIP 不直接携带同名 `Config.ini`，避免解压时先覆盖玩家设置。登录器只在目标 INI 不存在时生成默认文件；已有文件仅更新必要连接字段，继续保留窗口等设置。分发说明提示退出游戏和备份。旧导出 API 可保留兼容别名，但普通 UI 不再分开提供两类包。
- 继续校验同提交资源清单及摘要，拒绝路径越界、符号链接、混版和凭据泄露。

## 5. 两个单文件服务程序与发行验收

- Manager、Server 及高级 Channel 工具使用自包含单文件发布，将框架/项目依赖 DLL 和必要原生运行时打入对应程序；不用裁剪/AOT 改变反射、脚本或 WPF 行为。网页、模板、客户端资源、PVF、配置和存档仍可作为必要外部资源保留，常规用户主要接触管理器入口。
- 同步修改 Windows 客户端资源生成、五 RID 打包、Docker 构建、清单校验、归档测试与使用说明，不能只修改发布参数然后跳过完整性校验。校验单文件中所需依赖，拒绝空壳 EXE 和散装/单文件混合缺项。
- 实测 Windows/Linux 最终包的初始化、上传、启动失败回滚、重试、停止与玩家 ZIP；实际运行 Windows 登录器验证无需系统 .NET、根目录路径和原有补丁安装。macOS/ARM 仍只声明真实完成的交叉构建与结构校验。
- 本机现有正在测试的 Release、游戏客户端、存档与私有 PVF 不自动升级或覆盖。Runner 当前按用户要求暂停；不得为探索而恢复。需要实际 CI 验证时临时启动，完成后恢复暂停状态。
