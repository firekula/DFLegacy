# 客户端故障上报与 GM 后台诊断设计

日期：2026-11-09。状态：按用户修订推进；用户选择现有 GM 后台，并明确要求无需玩家点击同意，防止漏报。尚未发布。

## 2026-11-09 用户修订

- 基本故障报告默认自动收集、自动排队和发送，不增加首次授权弹窗或阻断启动的确认步骤。登录器设置展示接收站点、发送状态和关闭开关。
- 基本报告仅含本文白名单中的脱敏故障、版本、系统和硬件信息；禁止上传原始账号配置、聊天、截图或原始进程内存。既有历史共享日志不自动补传；只采集本版本当前 Windows 用户会话形成的新报告。
- 当前用户的关闭开关立即生效并阻止后续请求；重新启用只自动处理之后的新事故，旧队列可以手动重试。开关保存在用户 LocalAppData，不随整合包复制。没有记录视为启用，无需操作。
- 小型转储在真实故障时自动保存到当前用户本地，遵守数量、大小和时间预算；不会自动上传。提供导出路径/按钮供需要深入排障时使用，不为生成本地转储弹确认。自动接收端不提供任意内存附件上传，初稿的转储凭证/PUT 接口从本轮范围移除。
- 服务端接收缺省启用且受配额、限流、权限隔离限制，运营者可关闭。旧服务端不支持时不阻止游戏。
- 本轮按此修订实现并完成本地及 Gitea 隔离验证；不发布正式 GitHub/GHCR，不部署线上。原版故障入口研究关卡及如实披露未验证范围继续有效。

下方正文已按修订同步：自动上报脱敏基本信息，原始转储仅本地保存。

## 目标与已确认范围

用户希望客户端出现崩溃、掉线、启动或更新错误时，能够提交故障现场及系统、硬件信息，减少依赖玩家找日志和截图。用户已选择接入现有 GM 后台，随 Docker 部署。

延续当前隔离原则：基于 Gitea main 的 aca790d 开发，在 `codex/client-diagnostic-reporting` 分支工作；不修改第二章工作区、原始游戏目录或线上服务。本次批准设计不等于批准正式发布。实现验收先使用复制的客户端和本地服务；Gitea 更新链路测试使用独立测试标签，正式 GitHub 更新与 GHCR 不变。

以下数值、协议和交互均为实现建议，未经用户逐项指定。实现前以本文整体确认结果为准。

## 现状与缺口

- `src/DFLegacy.Ijl15/src/native_incidents.cpp` 已记录 x86 未处理异常、寄存器、模块偏移、有限栈地址及原生断线通知。当前先调用旧异常过滤器，旧过滤器卡住时可能无法写出自己的记录；还可能被后注册的游戏处理器覆盖。
- `src/DFLegacy.Launcher/Diagnostics/IncidentReporter.cs` 已有独立 error/networkerror/crash/update 文件、脱敏、去重、保留上限与异常退出关联，明确只落本地、不上传。
- `DetailedCrashCapture` 及 `tools/debug/crash_capture` 提供显式选择的外部调试捕获。当前工具会记录部分 first-chance 异常，这不等于真实崩溃；不能直接变成默认自动上报。
- 原游戏目录存在 BugTrap.dll 和 DumpReport.dll；尚未证明所有原生故障都经过同一入口，不能按 DLL 名称猜测 ABI 或覆盖原异常处理链。
- `WebPanelHosting` 同进程提供账号 API（默认 8081）、GM（18081）和玩家中心（18082）；GM 已使用集中权限策略。18081 在现有 Compose 中仅映射本地回环，玩家不能直接上传到它。
- 现有启动器使用 .NET 10；不能因为新增原生诊断程序就宣称整个登录器支持 Win7。硬件信息读取失败须降级，不增加游戏运行前提。

## 方案比较与选择

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 所有采集和上传放进游戏 DLL | 文件少 | 故障进程内做网络、压缩和系统查询更容易再次失败；不采用 |
| DLL 留最小现场，独立程序处理，现有 GM 查看 | 复用现有故障报告和管理权限，游戏退出后仍可处理 | 需独立队列及进程交接；推荐方案，接入现有 GM 已获用户选择 |
| 独立诊断平台 | 与游戏服务器完全分开 | 增加服务、账号和运维，不符合本次已选部署方式 |

采用第二种。复用现有诊断工具的安全边界和测试，不默认附加调试器。新增受更新清单管理的 `DFLegacy.Diagnostics.exe`，按登录器 x86/x64 打包；原生游戏现场捕获仍由兼容 x86 游戏的独立小程序完成。按集成裁定，托管助手采用各架构独立自包含单文件；现有登录器运行时嵌入单文件，无法直接共享。此方案保持固定入口修复且无需安装全局 .NET，代价是助手下载较大。

## 默认自动上报与采集范围

基本报告默认自动发送，不要求玩家点击。设置展示说明、接收站点、是否加密、队列状态和关闭开关；发送前再次读取当前开关。关闭或上传故障均不阻止进入游戏。

自动上报开关按当前 Windows 用户保存，界面明确标注其作用范围，缺省启用。这样复制整合包或切换安装目录也不能重新开启已关闭的选择。队列仍按安装实例、接收站点和启用代次隔离。热更新不能重置已关闭的选择，客户端服务端均可显式关闭，没有有效接收地址时保留本地报告。跨站队列不会自动迁移。

开关保存在当前 Windows 用户的 LocalAppData 下，不从 launcher.json、分发包或复制来的游戏目录导入个人状态。关闭后助手停止新请求并尽力取消在途请求；已送达的内容不会因本地开关变化被远程删除。

自动范围仅包括本版本当前用户启动会话产生的新事故；关闭后重新开启不自动补发关闭期间或旧代次的记录，旧队列保持 held-local，可手动重试。无法证明来源属于当前用户的共享目录历史日志不进入上传候选。

| 类别 | 基本报告允许内容 |
| --- | --- |
| 身份与版本 | 随机事件 ID、会话 ID、时间和时区、报告格式版本；安装版本、进程位数、补丁和 PVF 哈希；服务端版本无可靠证据时为 unknown |
| 故障 | 证据类型、异常码、故障模块文件名及哈希、模块内偏移、有限调用栈地址、阶段、失败次数、脱敏后的少量上下文 |
| 系统 | Windows 版本与 build、系统及进程架构、语言、进程运行时长 |
| 硬件 | CPU 型号及逻辑处理器数、总内存和故障时可用内存、显卡型号/驱动版本/显存（读取失败为 unknown） |
| 显示 | 游戏分辨率、窗口模式、实际渲染后端与适配器、DPI |
| 网络 | 协议、端口、失败阶段、socket 错误码、重试和字节计数；不含包体 |

不主动采集账号、密码、令牌、机器名、Windows 用户名、MAC、硬件序列号、完整进程列表、聊天、截图、游戏存档或完整配置。模块仅上传文件名/哈希/RVA；日志中的安装路径、用户目录、URL 参数和已知凭据需脱敏。服务器接收连接可见来源 IP，仅用于有界限流，不写入诊断正文，不默认启用带请求体的访问日志。

基本报告使用结构化白名单和限定日志片段，不能把现有目录中的所有 .log 原样打包。成功的更新记录留本地，不自动当故障上传。正常退出、频道切换、正常 EOF、主动取消和可处理异常不得计入崩溃统计。

真实故障时自动保存受限本地转储，不为捕获弹窗。转储可能含敏感内存，无法承诺全面脱敏，因此本轮助手与接收端均不提供转储上传；需要深入排障时可由玩家主动导出并另行反馈。设置中提供保存路径和采集开关。

## 原生捕获与辅助进程

1. 启动时预备辅助进程、仅当前用户可访问的 IPC 以及预分配的异常上下文区域。关联目标 PID、创建时间、会话随机值和客户端路径，避免 PID 复用或串到另一游戏实例。帮助程序只观察本次启动的游戏。
2. DLL 在故障入口复制最小 EXCEPTION_RECORD/CONTEXT 并通知助手；不在异常线程枚举硬件、压缩或联网。系统与显卡信息在正常启动阶段异步缓存，采集超时不阻塞游戏。
3. 最小现场通知必须发生在可能阻塞的旧处理器之前，但标为 provisional。允许异常线程在调用旧处理器前有界等待：基本记录交接最多 2 秒，启用本地小型转储时含转储的总等待最多 5 秒；按单次故障的单调时钟总预算控制，超时照常交回原链。辅助进程先确认上下文已复制并落临时文件，不能依赖旧处理器返回后目标仍存活。旧处理器返回 CONTINUE_EXECUTION 时撤销并清理候选现场，不入上传队列；未处理结果、对应故障窗口或与候选现场关联的进程终止才能确定事故级别并发布记录。第一次机会或可恢复探针不直接确认为 crash。原处理链仍被调用，不吞异常，不把失败伪装成正常返回。
4. 已验证未处理异常、可信原版崩溃入口、异常退出分别记录证据等级。旧处理器卡住时，独立助手可关联游戏自己显示的 CrashSender/BugTrap 故障窗口；窗口归属必须匹配目标进程，仅据窗口识别的现场标为 crash-dialog/snapshot，不能冒称已定位原始故障指令。
5. 原版 BugTrap/DumpReport 兼容入口核查是实施计划的前置研究关卡：输出当前 ACT1 的可执行文件/DLL 哈希、导出/调用点证据、异常链顺序，以及隔离副本中受控故障与窗口的关联记录，再确定具体 Hook。补丁只匹配已验证签名。未知版本不盲目 Hook，回退到异常退出/窗口证据和显式详细诊断。如果当前 ACT1 也找不到可靠入口，其他链路可继续实现，但精确现场捕获必须标为阻断并向用户说明，不能把窗口快照冒充完成或自动发布。完整支持当前 ACT1 故障路径是验收项，不能用“新增一个异常处理器”代替该验收。
6. 本地小型转储默认开启，在外部进程生成，可从设置关闭；与人工详细调试模式独立。不保存整个堆，不遍历无关进程。保存目标 5 秒内、成品不超过 16 MiB；回调限制并非硬实时保证，助手另设有界超时并丢弃超限/不完整文件。超时只终止本次采集助手，不终止或恢复执行游戏进程；结果明确显示现场缺失。
7. 游戏异常退出后，助手完成当前开关允许的报告入队并在有限时间内退出；发送失败留待下次启动。关闭上报不杀游戏，不循环拉起崩溃的诊断程序。强制终止、断电等可能仅有启动器侧摘要，保留“原因未知”。

加载与卸载顺序、旧过滤器返回/阻塞/替换、栈溢出和助手不可用均以专用故障子进程测试。已有详细调试器模式作为人工排障保留，不能与自动助手同时抢占同一调试会话。

## 客户端队列、传输与恢复

- 队列独立于安装事务，保存于当前用户 `%LOCALAPPDATA%/DFLegacy/Diagnostics/<安装实例随机ID>/`，目录仅该用户及系统管理主体可访问。用户身份及本地路径不上传；复制安装目录不会继承其他人的队列。基本上报不持有安装锁；每个用户/安装实例只有一个队列写入者和一个上传者。`.dflegacy/diagnostics/` 作为历史/预留诊断目录仍必须排除更新和资源导出，不能从中无条件导入旧报告。
- 助手仅接收已脱敏的结构化记录、目标站点和有界会话能力，不读取整份账号配置；通过当前用户限定的 IPC 交接，不把账号或秘密塞进进程参数。
- 状态为 pending / sending / sent / held-local / rejected。临时文件原子更名入队；助手中断可恢复。发送中的文件不可被保留清理删除。
- 每个报告在发送前冻结内容和 SHA256；重试使用同一事件 ID 和哈希。托管生产者在一分钟窗口内复用同一合并事故 ID，自动正文固定 occurrences=1；窗口内再次通知只增加本地丰富日志的计数，不修改冻结正文。原生通知按当前会话类型/错误码有界合并。后台显示合并事故数，不能当作原始通知频率。
- 默认最多 100 份、总计 32 MiB、14 天；详细转储最多 2 份且单份 16 MiB。达到上限清理已发送最旧报告；未发送报告过期或超额淘汰需在本地记录计数，不能声称仍待发送。
- 单并发，默认限速 64 KiB/s，基本报告压缩后不超过 256 KiB、解压后不超过 1 MiB。单次连接/请求有超时；一次运行最多 3 次尝试，指数退避加抖动，429 遵循有上限的 Retry-After。断网、5xx 留队；格式拒绝不无限重传。
- 上传成功需要服务器确认已持久化。响应丢失时重试不产生重复报告。正常启动和登录不等待上报完成。
- 已收集事件的有界会话回执先于入队持久化；队列清理后不可用同 ID 重冻不同正文。会话回执写入后若队列落盘失败，该事件放弃自动重冻，保留本地证据。会话登记在新会话注册时独立清理死亡或已完成且无存活游戏的记录，不依赖上传资格；保留 PID 与创建时间匹配的游戏及独立 captures。
- 客户端按每个服务器配置解析 `DiagnosticsServiceUrl`，缺省沿用该服务器的玩家账号 API 基址。队列固定最初接收站点，切换服务器不把旧报告发给新站点；URL 禁止带凭据，不跟随跨站重定向。
- 兼容当前公网 HTTP 8081 的基本报告，设置明确显示“未加密”；推荐 HTTPS。任何 HTTPS 证书错误都不绕过或自动降级。
- 诊断接收服务故障不改变游戏服务器连接、更新来源或离线启动策略。

## 接收接口与权限

玩家接收口沿用账号 API 监听器（默认 8081），GM 界面保持 18081。无需新增 Compose 端口。部署管理 18080 和玩家中心 18082 不承担诊断接收或浏览。

拟定路由：

| 路由 | 权限与行为 |
| --- | --- |
| POST `/api/client-diagnostics/reports` | 仅在账号 API 监听器且服务启用时开放；接收基本报告，允许登录前故障上报；返回随机回执与状态，不接受原始转储 |
| GET `/api/admin/diagnostics/groups` | 仅 GM 监听器且 Admin 权限；分页查询、分类过滤 |
| GET `/api/admin/diagnostics/reports/{id}` | 同上，查看结构化详情 |
| GET `/api/admin/diagnostics/reports/{id}/download` | 同上，附件下载；不放在 wwwroot |
| PATCH `/api/admin/diagnostics/groups/{id}` | 同上，标为新问题/处理中/已处理并记录管理员及时间 |
| DELETE `/api/admin/diagnostics/reports/{id}` | 同上，删除指定报告正文，保留有期限的去重摘要，界面需二次确认 |

基本上报不使用游戏密码或 GM token。匿名接收是明确的取舍：启动失败也能报告，但客户端事件不能作为可信审计或奖励依据。格式验证、严格字节上限、来源和全局限流、磁盘配额共同约束滥用。

建议缺省限流：单来源每分钟 5 份/每小时 30 份，全局每分钟 10 份/每小时 120 份；并发上传 2 个。来源只用真实连接地址；反向代理只信任显式配置的代理，不信任任意 X-Forwarded-For。共享出口被限流会排队重试，不影响游戏。

回执按事件 ID 与内容哈希幂等：同内容返回原回执；同 ID 不同内容 409。POST 响应丢失时重发同一冻结正文，可重新取得同一回执；回执不是查看报告的授权。过期/删除时返回明确终止状态，不自动新建事件绕过期限。

详细转储保留本地供玩家另行反馈；不暗中改端口或跨站发送。HTTPS 反向代理必须列入可信代理配置后才能使用其协议头判断安全连接。

上传限额在读取正文和解压前后分别执行，禁止自动不受限解压。服务端不解压任意 ZIP，不接受客户端磁盘路径，也不从正文中的 URL 下载资源。不接收原生转储，不在 Web 请求内执行符号解析。

## 服务端存储与 GM 功能

配置集中在 `DFLegacy:ClientDiagnostics`：Enabled（缺省 true）、StoragePath、RetentionDays、MaxStorageBytes、MaxReportCount、基本报告上限及速率。路径默认从持久化数据根解析到 `diagnostics/`，容器中为 `/app/data/diagnostics/`。

不把诊断数据写进 `state.json`，不取得角色/邮件/奖励的存档锁。脱敏报告正文落独立目录；索引用有界的独立持久化文件和可重建摘要，不新增数据库服务。写入使用临时文件+原子提交，返回成功前完成持久化；重启后恢复半完成入库和索引。读取分页，不在每次列表请求遍历磁盘。

建议总上限 256 MiB、2000 条；基本报告保留 14 天。服务端不保存转储。配额包含临时上传，预留原子替换空间；定时清理与下载/上传互斥，接收关闭时仍清理已存报告。空间不足拒绝新上传并提示后台，不影响游戏数据。

已删除/过期记录的幂等摘要至少保留删除后 30 天（长于客户端 14 天自动队列寿命），重复 POST 返回 410，客户端停止自动重传；下载接口仍不暴露已删除正文。去重摘要有独立 50000 条及字节预算，计入总配额；容量不足时拒绝新接收，不提前丢弃承诺期限内的摘要。客户端报告超过 14 天不再自动发送，必须玩家重新手动提交为新事件。30 天摘要到期后不承诺永久识别恶意伪造的旧 ID，不能把有界去重描述为永久墓碑。验收使用可控时钟覆盖 14/30 天边界。

GM 增加“客户端故障”入口：按时间、类型、客户端版本、系统、显卡和处理状态筛选；列表显示指纹、合并事故数、最近时间、版本和证据级别；详情显示脱敏系统信息、错误摘要和关联报告。报告文本始终转义渲染，禁止执行 HTML。JSON 下载仅管理员可用并设置附件响应、不缓存；删除和处理状态修改留下不含正文的管理员操作记录。

崩溃指纹使用补丁/模块内容版本、异常码、模块偏移和可用的前几层模块相对栈；不能用 ASLR 绝对地址聚类。网络问题按阶段/协议/端口/socket 错误归并，缺字段用 unknown，不能把所有未知故障归成同一已知原因。UI 的统计基于持久化幂等记录，不因刷新或重传增加。

GM 新增脚本需加入独立端口精确白名单，并使用真实页面引用资源的 HTTP 回归；玩家中心和公共账号监听器均不能访问诊断管理 API，即使持有 GM token 也遵循监听器隔离。

## 更新与兼容

- 新组件、DLL 和清单通过现有 V4 x86/x64 normal/test 管线生成，配置迁移保留账号、服务器、端口及已保存的上报开关。运行时队列、个人开关文件和转储永不作为更新资源上传。
- 服务器未升级、接收被禁用或返回不支持时继续游戏，只保留本地报告。不会因为上报不可用改用其他站点。
- 为每个构建私下保留与 DLL 哈希对应的符号文件和构建 ID，方便分析自己的 DLL；原版游戏没有符号时明确只能给模块/偏移和反汇编线索，不承诺自动还原完整函数名。
- 本地测试的接收站点与生产严格分离；开始真实上传测试前确认显示的是回环地址和测试存档。Gitea 只分发测试程序，绝不存放玩家报告或转储。

## 验收标准

1. 原生受控访问冲突、栈溢出、过滤器返回 CONTINUE_EXECUTION、旧过滤器阻塞/替换、异常退出、原版故障窗口但进程仍活着：验证证据级别与可用现场。正常退出、切频道、可恢复异常不进入崩溃统计。不能以伪造日志代替原生故障测试。
2. 缺省自动发送、关闭、重新开启、换站点、历史/其他用户报告排除、HTTP 提示及 HTTPS 失败：用真实网络观测确认不越界发送，不出现首次同意弹窗。
3. 两架构登录器、x86 游戏、多开、PID 复用、助手丢失/损坏、无权限、硬件查询超时：报告降级不影响正常启动，不附加或终止无关进程。
4. 断网、429、5xx、慢网、成功响应丢失、队列/服务端写入中断与重启：同一报告最终只计一次，不无限重试、不阻塞游戏。缺失原始现场明确显示。
5. 公共接收接口验证字节/解压/并发/配额、路径和内容安全；匿名/玩家/GM 的读写权限与三监听器隔离；XSS、伪造头、未知字段、同 ID 不同正文都需真实 HTTP 测试。
6. 本地 GM 完成列表筛选、归并、详情、下载、标记、删除与重启持久化。用预置假密码/路径/令牌检查实际上传字节和落盘内容，确保基本报告脱敏；受控原生故障生成本地转储，网络中不得出现转储内容。
7. Gitea 四变体更新验证组件到位、故障助手被删除后可修复、个人开关和未发送队列保持。操作仅限隔离副本；正式 GitHub、GHCR 与线上数据不变。
8. 提供图文报告，分别列自动化、实机和未验证范围。Win10/Win11 及旧系统未实测的项目如实标注；自动报告改善定位，不等于修复最初的剑魂战斗崩溃。
