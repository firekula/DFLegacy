# Debug跨区域自动移动验收

用户要求先验收debug跨区域移动，停止由模型手工拆分城镇路段，再接续U04掉落验收。

已取得实机RED：现有同区接口只发一次(785,160)，B自动从艾尔文防线1/0进入赛丽亚房间1/1，没有方向键过门；消费者随即抛context_changed，不能续走。证据位于独立debug-cross-area命名空间。原版有效落点的479EF0→478F70→B5F0A0与当前接口移动核心一致；4795F0持续朝终点更新方向，碰撞逐轴回退，没有全局拐点搜索。因此区域内凹形地面和跨区续行需由操作接口自动规划，不能继续让模型手工发路段。

提供一个公开命令：最终town、area、x、y为唯一目的地。接口从实际客户端Script.pvf读取town列表、各area地图、virtual movable area和town movable area，自动算区域路线与安全拐点，逐段调用已有原生自动移动；门内目标由实际矩形交集确定，不用方向键过门，不发业务包，不修改位置、PVF或存档。旧同区96字节DLNV接口保持兼容，路径执行层使用同一控制锁。

执行必须绑定PID、进程创建时间、UID、user/actor/context；仅在预期区域切换且代次递增时接受新map/generation。每段需有原生接受证据，并以新鲜实际状态确认到达或预期过图。失效快照、身份变化、无路径、人工移动/目的地覆盖、非预期区域和过期均中断，不能报告到达，也不能继续后续段。原生方向键中断须阻止路线恢复；本轮不新增未经证明的强制取消写状态。

范围是当前ACT1客户端的城镇地面与普通通道；不规划经过副本作为中转，不绕过等级/任务门槛、不处理未知交通模式。静态规划不能保证动态障碍可通，失败需明确返回。关键验收保留原生截图，其余使用debug数据、原生回执和输入次数证明。

验收：先补RED/GREEN，覆盖PVF边界、凹形走廊、门点合法性、预期/非预期换区、同坐标新代次、身份替换、锁冲突、人工中断与过期；再在实际PVF做规划回归，并在A/B两端各通过单条最终目的地指令跨多个区域和回程。只有完整目标到达后计为通过，底层requested或一次过门均不代替最终验收。
