# 原生客户端结构化状态

用户要求扩充debug.dll，减少截图分析和操作延迟，以房间、敌人、玩家和技能数据驱动后续双端／四端测试。此前已授权连续实施与测试；本设计中的实现选择由开发侧采用现有项目惯例决定，不新增确认等待。

## 当前状态与方案

当前debug.dll ABI v2的Frame只有scene、区域UID、bossDead和本地进图时间；服务端快照主要是箱怪表。外部probe已验证HP、死亡、位置、原生对象、门及技能等级，但每次重新创建进程读取和输出完整JSON成本较高。现有overlay在死亡actor.map暂为0时会隐藏，不能把这一现象解释为离开副本。

采用debug.dll内的只读采集和结构化文件输出，接入既有DebugRender与工作线程；保留ABI v2及既有面板协议。已证原生字段在游戏线程有界采样，工作线程输出原子JSON；外部控制只读新鲜快照，并继续使用既有IJL15原生输入。服务端房间编号等信息独立注明来源，不能将其当成客户端已经应用的状态。

新capture先于旧Frame.scene／面板可见性的返回门禁，独立读取真实场景。首版沿用EnableDebugOverlay负责加载DLL，新导出另由`[DebugOverlay] ExportState=1`显式启用；面板收起／隐藏不停止已启用导出。未加载DLL时消费者报告无数据。

仅扩充外部probe能更快起步，但无法解决反复启动、跨进程读取和大量日志的问题；仅扩服务端箱怪表无法观察客户端死亡、位置和技能状态。新开网络监听没有必要，沿用本地调试目录。

## 首版字段与边界

- 版本、PID、进程启动身份、采样序号、采集UTC与单调时间、独立写盘时间、采样有效性与场景。序号与采集时间仅在新采样时更新，worker不能用重写旧数据延长有效期。
- 原生Stage/Map身份及场景代次；服务端匹配且新鲜时另带run、dungeon/map ID、room坐标和通关状态。
- 本人和最多四个队员的区域UID、对象身份、HP／最大HP、死亡、地图关联、已验证坐标；未知MP等字段显式未知。
- 当前地图敌人的UID、脚本编号、HP、死亡、激活、坐标、当前动作、队列动作及原始authority token；不将token推断为owner UID。
- 四方向门的矩形、开放掩码、集结阶段及已验证同房活人数量；不足以判断时返回未知，不直接过门。
- 门mask只表示出口拓扑存在，不等于战斗结束后可通过；另读取`map_clear_state`原始保护整数，首版保留原值，不推断其所有阶段语义。
- 已学技能ID和等级；技能冷却／可用性必须补齐原始PE读取与时间基准证据再输出。等级不等于技能可用；首版未证字段为null/unsupported。

服务端context只在原有区域UID、进图时间及1.5秒时效条件成立时独立附带，仍标记`matched=false`：现有字段不足以证明它与客户端已应用的具体房间一致。首版自动控制只用原生门／地图数据，不用server context中的房间号推断客户端已换房。

死亡时actor.map为0可表示地图暂时脱离。若稳定UID、user→actor和Stage绑定仍存在，记录detached与dead；不提供有效位置，不一般化取消原map归属校验，不把它伪装成Town或存活。

## 开销和生命周期

默认关闭新导出，用客户端现有调试配置显式启用。采样目标每200ms一次，限定对象与技能扫描上限；不在游戏线程写文件、不阻塞等待控制器。运行时无调用游戏业务函数、写HP／位置／技能状态或注入协议的功能。所有原始读取有边界、镜像保护整数与布局校验；坏对象只影响相关字段，整体身份变化使快照失效。

ABI兼容不代表内存布局兼容。新capture须通过本版原始PE身份及关键未修改函数签名／对象vtable门禁；测试宿主和其他EXE输出unsupported，不探测硬编码地址，不影响旧面板。门禁不以SEH替代。未证职业／对象类型保留unknown。

每客户端按PID独立输出。游戏线程用TryLock，忙则跳过发布并记计数；工作线程在锁内只复制有界结构，序列化和原子替换在锁外。数组截断必须显式标记，任何依赖完整成员／怪物表的集结或清场判断均返回未知。关闭时沿用现有停止／等待／销毁顺序，失败保留代码不强卸载。新控制工具验证PID、启动时间、区域UID、序号及新鲜度，输出紧凑摘要或变化事件；过期／换角色／换房时停止依赖旧状态。消费者使用同机单调采集时间，UTC跳变不使旧状态变新；保留UTC用于证据时间线。

## 验证

对采集器的内存读取、损坏／过渡对象、保护整数、数组上限、重复ID、浮点与坐标provider、死亡脱离、场景代次及技能未知状态做确定性测试。输出与消费端覆盖原子读取、身份／时效拒绝、变化摘要和多客户端隔离。

专项覆盖停止渲染而worker仍运行、旧结构重复输出、UTC跳变、TryLock竞争、列表截断和错误PE，均不得让控制器将旧／不完整数据视作新鲜可执行状态。

真实两端核对Town→副本→换房→死亡→复活→回城，和既有只读probe短窗口交叉读取；保留少量原始截图作视觉验收，不能用数据替代未知弹窗的判断。测量采样及写盘开销，记录实际结果，不预先承诺帧率／延迟数值。后续U01/U03/U04和怪物同步使用该接口，四客户端掉落另行验收。
