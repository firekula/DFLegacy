# 第二章隔离测试定位与指定敌人清理

用户明确要求停止手动移动、手动击杀，复用第一章的瞬移和指定敌人秒杀以提高四窗验收效率。沿用已授权的隔离测试宿主与原生主线程入口；不更改普通交付、主线、线上、日常客户端、资源或结算计时。

第一章已采用角色原有定位入口、原有完整位置发布入口，再检查同房观察者。第二章保留这一行为，逐一核对自身入口和结构，不能复制第一章地址。现有第二章单目标清理继续保留，补齐指定目标选择、四窗死亡观察和可复用命令。

选择扩展现有私有宿主，不另建控制框架。仅限当前副本、自身角色定位；不跨地图、不直接修改存档或奖励。请求绑定进程创建时间、运行标识、近期快照、自身身份、地图与场景。目标必须在当前房间、存活且由执行端持有。坐标为有符号16位整数。失效身份、重复请求、未知动作和旧接口均拒绝。定位前检查原生发布路径可用，定位后调用原生完整发布；返回部分成功时不得重试未确认的动作。

宿主导出当前位置、同房玩家及敌人状态。工具区分命令调用、原生变化、四窗同步；只有各窗身份/房间未变化且观察结果匹配才报告同步。此结果仍不代替服务端死亡、掉落、结算和持久化证据。

验收：原图像坐标/发布约束检查、拒绝路径测试、工具请求/同步测试、保留原有清理测试；新构建正常启动后实测四窗定位与指定普通怪/领主清理。先前换房异常保留为未解决的独立观察，禁止通过改本地状态或计时掩盖。

执行补充：为遵守“不手动移动”，初始化进副本前提供单人 `walk` 准备动作，复用第二章已验证的城镇原生目标校验、自动行走入口和启用方式。独立绑定城镇自己的角色指针/用户字段/区域链，只接受当前地面或原生出口范围；原有行走逻辑完成移动、同步和出口转换。它不调用副本瞬移或清理入口，不把“寻路已开始”写成位置已同步，也不导出未验证的城镇生命值为零。
