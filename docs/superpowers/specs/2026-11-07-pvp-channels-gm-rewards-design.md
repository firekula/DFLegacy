# 第一章：决斗频道、GM 胜点与全服邮件

状态：用户已于 2026-11-07 确认按方案实现并自动测试。工作区为第一章隔离区，不操作第二章工作区或线上服务。

## 已确认的需求

- 决斗场采用分级频道，并提供覆盖全部段位的自由频道。
- 18081 GM 后台增加向指定角色发放决斗胜点的功能。
- 全服邮件发送给本次发送时所有现有角色，每个角色一封，包括离线角色；之后新建角色不补发。

## 现状与选定方案

当前服务端只发布决斗频道 51。当前 PVF 的第一档决斗频道只允许段位索引 0～4，其余角色会被客户端提示“等级不符”；这不是人物等级限制。当前 PVF 的最高决斗段位索引为 30。

已比较“分级＋自由”和“全部无段位限制”两种方案，用户选择前者。保留现有单进程服务和 GM 页面，扩展频道配置、持久化操作及界面，不另建服务。

以下具体分档及端口为实现建议：

| 决斗频道 | 编号 | TCP 端口 | 决斗段位索引 |
| --- | --- | --- | --- |
| 初级 | 51 | 7004（现有） | 0～9 |
| 中级 | 52 | 7110 | 10～19 |
| 高级 | 53 | 7111 | 20～当前 PVF 最高段位 |
| 自由 | 55 | 7112 | 0～当前 PVF 最高段位 |

自由频道放宽进入段位限制，对战与胜点结算沿用现有规则。每个频道拥有独立的房间列表，禁止通过房间 ID 跨频道加入。只扩展当前已经实现的决斗玩法，不增加公会战或观战玩法。

## 决斗频道及客户端

- 频道列表、监听端口和 PvP 会话识别使用同一份频道配置，校验与其他服务端口冲突。
- 保留现有普通地区频道 7001、7100～7105，以及原决斗端口 7004；新增 7110～7112/TCP。
- 更新当前 PVF 的 `etc/channel_info.etc`、`etc/pvpchannellist.etc`，校对各服务器分组的决斗条目顺序、名称及段位范围；服务端也按对应频道校验进入资格。
- 从当前已发布 PVF 导出独立新文件，不覆盖用户原文件。记录前后哈希，并验证条目、任务、掉落和偷学技能未被意外改动。
- 管理后台及离线打包器生成的客户端包含四个决斗端口。现有客户端自动更新时，在运行时补齐标准决斗端口，不覆盖 `launcher.json` 中的服务器、账号及自定义配置；同时测试未启用中继的路径。
- 客户端更新同时包含配套 PVF。部署说明明确服务端也要选择同一 PVF，并放行新增 TCP 端口。

## GM 发放胜点

- 在 18081 GM 后台增加角色选择、当前胜点、发放数量及提交结果。
- 采用“增加指定数量”，只修改可消费的 `VictoryPoints`，不修改决斗经验、段位、胜负记录。
- 在线、离线角色均可发放；在线会话刷新显示，并保证发放不被较旧的会话存档覆盖。
- 数量必须为正整数，拒绝溢出；失败不能改变存档或余额。
- 同一操作 ID 重试只发放一次，拒绝使用同一 ID 提交不同内容；保留可核对的操作结果。

## 全服邮件

- 复用现有邮件表单和附件查询，增加“指定角色／全服角色”发送范围。
- 复用现有发件人、正文、金币、普通物品、装备、时装和宠物蛋校验。
- 发送前预览接收角色数量与邮件内容，确认后对现有角色建立固定接收名单。
- 批量投递采用一次批量存档提交，避免每个角色都重复保存整个存档；在线角色收到新邮件提示，离线角色下次登录可见。
- 各角色的装备、时装、宠物蛋等附件实例 ID 独立生成，不能复用同一个物品实例。
- 邮箱已满等情况按角色返回失败原因，不清空已有邮件；显示成功、失败数量和失败名单。
- 同一批次 ID 重试不重复投递。部分失败时提供“仅重试失败角色”，新批次明确关联原批次，不再次发送给原批次已成功的角色，也不补发给后来创建的角色。
- 持久化写入失败时，不发送成功通知；结果不确定时不得自动再次发放奖励。
- 玩家身份不能调用这两个新增 GM 功能。测试邮件只发到隔离测试存档。
